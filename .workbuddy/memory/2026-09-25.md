# 2026-09-25

## chartdl 右侧「下载内容」面板三处修复（用户报：曲目标题被下移、挡到 checkbox）

根因是 09-19 那版 `4ae72f0`（钉住页脚 + 滚动 body）留下的：标题被挪进滚动容器
`gDetailBody`，但坐标仍是**分组框坐标**。

1. **标题挡 checkbox（用户报的）**：`gDetailTitle` 当时用 `createInGroup` 创建（父=body），
   而 `SetWindowPos(gDetailTitle, group, baseX, dp(18), ...)` 里第二个参数是
   *hWndInsertAfter*，不是父窗口 → 实际坐标变成 body 空间，绝对位置 = body(42) + 18 = 60，
   而第一行 checkbox 在 46..70 → 正面压上。
   修：标题改成**分组框的子控件**（`createInBox`），`hWndInsertAfter` 传 nullptr；y=dp(18)
   本来就是分组框坐标，bodyTop=dp(42) 在它下面，语义（滚动行从标题下面滑过）恢复。

2. **空状态整块面板空白**（同一个提交的副作用，用户没提但我顺手修了）：`updateDetailPanel()`
   启动时**根本没人调用**（只有列表选中变化时调），而 `layoutChildren()` 里那句
   `if (gDetailSong >= 0 || gDetailWantedHeight > 0)` 把空状态挡在门外 → 标题、曲绘、
   元数据全是创建时的 10x10，什么都没画。改成无条件调 `layoutDetailRows()`。

3. **「下载内容」标题左边的幽灵 checkbox**：分组框左上角一直有个 ~9x10 的小对勾。
   查法：临时加 `CPPSEKAI_WIN_DUMP` 枚举子窗口 → 那个位置**没有任何窗口**，
   说明是窗口表面上的**陈旧像素**：面板里的控件都是创建即 `WS_VISIBLE`，在第一次布局
   把它们搬走之前先按 10x10 画过一帧，而那块区域后来再没被带擦除地重绘过。
   修：面板内所有行控件**创建时不带 WS_VISIBLE**，由 `placeRow` / 标题那句
   `SetWindowPos` 加 `SWP_SHOWWINDOW` 放出来（空状态另外把 5 个难度框 `SW_HIDE`）。
   顺带给 `saveWindowPng()` 的 `RedrawWindow` 补上 `RDW_ERASE`（原来只有 RDW_INVALIDATE，
   截图会把这种残留一起拍进去，无头自检不能报不存在的像素）。

验证：`--screenshot` + `--select <row>`（这个开关 09-19 就有），旧版对照用
`dist/CppSekai-2026-09-24/chartdl.exe`（18:22 那版更早，连 --select 都没有）。
空/选中/192dpi 三种都截了，`--dpi 192` 下仍是设计内的滚动钳制（expert 行被页脚切一半，
09-19 就确认过是预期）。0 警告。

**可复用的一条**：chartdl 里排查「画面上有东西但枚举不到窗口」→ 先怀疑窗口表面的陈旧像素，
控件级修复是「创建即隐藏」，工具级修复是 `RDW_ERASE`。

## chartdl：最小化再还原，左右两栏宽度自己变了

用户报的现象，根因在 `layoutChildren()`：`gListWidth` / `gBottomHeight` 这两个
**拖出来的宽度**是就地 clamp 的（`gListWidth = clamp(gListWidth, 200, width - …)`），
而最小化时 Windows 发的 `WM_SIZE(SIZE_MINIMIZED)` 带的是 **0x0 客户区**
（用 EnumWindows 查过那个最小化实例：`GetClientRect` = 0,0）→ 一次 0x0 排版就把它们
钉到地板（歌曲列表 200px、日志条 90px），还原后不会自己长回来。
实测：列表右缘 812 → 208（208 = margin 10 + minList 200），385,492 像素变了。

修：`layoutChildren()` 开头 `if (IsIconic(hwnd) || width <= 0 || height <= 0) return;`。
正常缩放碰不到（`WM_GETMINMAXINFO` 卡了 860x560 下限）。

**顺手发现的同类行为（没改，等拍板）**：把窗口拖到 ~890 客户宽以下时，
clamp 会就地改小 `gListWidth`，窗口再放大回去列表**不会**恢复原来的宽度
（实测 812 → 664，放大回来仍是 664）。要修的话得把「用户的偏好宽度」和
「当前能显示的宽度」拆成两个变量，`splitterRects` / `hitSplitter` 也要跟着用后者，
不然热区和实际分割线会错位（那个文件里专门注释过这个坑）。

新增 `.workbuddy/tools/chartdl_minimize_check.py`：真的给运行中的窗口发
`WM_SYSCOMMAND SC_MINIMIZE/SC_RESTORE`，前后各 PrintWindow 一张，断言「列表右缘不变
+ 整图像素 0 变化」；`--no-minimize` 是对照组（什么都不发，证明 diff 不是截图噪声）。
它按 **PID** 认自己启动的实例——chartdl 允许多开，按标题找会抓到别人/残留的窗口
（那个最小化的实例就骗过我一次：客户区 0x0，PrintWindow 直接报 "cannot write empty image"）。
