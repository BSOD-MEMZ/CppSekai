# 2026-09-17

## 多人游玩（同机多窗口联机）—— 新功能

需求：多开之后能一起打。第一个窗口（房主）选曲 → 其它窗口选难度 → 一起开始；
延迟要低；BGM 只让主实例放。

实现（细节全部写进 AGENTS.md 的「多人游玩」一节，这里只记要点/坑）：

- 新增 `platform/Party.hpp/.cpp`（共享内存总线）+ `game/PartyScreen.hpp/.cpp`（房间 UI），
  `main.cpp` 加 `AppState::Party` 与时钟跟随；`build.sh` 两个新源文件。
- 传输用命名文件映射 `Local\CppSekai.Party.v1` + 每实例一个座位，**没有 socket/管道/序列化**，
  状态变更就是往共享页写 LONG。控制块 seqlock，座位字段各自主人写。
- 起奏同步用 **绝对 QPC 值**（全机唯一）：房主发布 `startCounter`，各窗口到点各自
  `beginSessionClockAt(startCounter)`；房主每帧把自己的 songTime+采样 QPC 发出去，
  成员用 QPC 外推 + 缓变偏移跟上 → 实测 **中位 2.7ms / 最差 6.5ms**，暂停时成员画面钉死 0ms 位移。
- BGM 只有房主：成员 `startSession(..., allowMusic=false)`；选曲试听、SMTC、任务栏进度同理。
- 开关：设置→系统→多人游玩 / `--party`；打开顺带允许多开（每个窗口登录不同用户）。
  只有一个人的房间 = 原来的单机流程，一行没改。
- 暂停只能房主按；多人下强制关掉"失焦自动暂停"；房主关窗后成员退回本地时钟。

### 两个真 bug（都是验证工具抓出来的）

1. **0 值时钟包**：房主还没发布时成员读到的 clock 字段全是 0，拿去算 → 误差几个小时，
   成员时钟直接跳到 +3993s，整首歌全 MISS。修：控制块加 `hostClockValid`，
   另外 `|error|>5s` 的包一律丢弃。
2. **音乐起播瞬间房主音频时钟跳一帧**（`AudioEngine::update` 里 `mMusicStartFrames = 现在`，
   30fps 下 25ms），恰好是第一批音符要判的时候，而 3% 的慢速修正要好几秒才吃完。
   修：起奏前自由对齐（只有开幕卡在看时钟），起奏后 3 秒内用 50% 速率修正。

### winsend 的三个坑（.workbuddy/tools/winsend.c 已修）

- SDL 的鼠标按键位置取自**系统光标**，不是 lParam → `click` 必须先 `ClientToScreen` +
  `SetCursorPos`。
- SDL 没有键盘焦点就**静默丢弃** `WM_KEYDOWN` → 要 `AttachThreadInput` 再
  `SetForegroundWindow`（单纯调用会被拒），必要时补 `WM_ACTIVATE`+`WM_SETFOCUS`。
- `ShowWindow(SW_RESTORE)` 的**还原动画**期间 `ClientToScreen` 是旧位置 → 点击偏上百像素；
  只在 `IsIconic()` 时还原，`place` 之后等 2s。
- 新动作：`focus` / `place x y` / `rect`；另外加了 gated 日志 `[ui] mouse down at x,y`，
  专门用来区分"事件没到"和"到了没命中"。
