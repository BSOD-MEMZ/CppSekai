# 2026-09-17

## 多人游玩（同机多窗口联机）—— 新功能

需求：多开之后能一起打。第一个窗口（房主）选曲 → 其它窗口选难度 → 一起开始；
延迟要低；BGM 只让主实例放。

实现（细节全部写进 AGENTS.md 的「多人游玩」一节，这里只记要点/坑）：

- 新增 `platform/Party.hpp/.cpp`（共享内存总线）+ `game/PartyScreen.hpp/.cpp`（房间 UI），
  `main.cpp` 加 `AppState::Party` 与时钟跟随；`build.sh` 两个新源文件。
- 传输用命名文件映射 `Local\CppSekai.Party.v1` + 每实例一个座位，**没有 socket/管道/序列化**，
  状态变更就是往共享页写 LONG。控制块 seqlock，座位字段各自主人写。
- 起奏同步用 **绝对 QPC 值**（全机唯一）：房主发布 `startCounter`，各窗口到点各自
  `beginSessionClockAt(startCounter)`；房主每帧把自己的 songTime+采样 QPC 发出去，
  成员用 QPC 外推 + 缓变偏移跟上 → 实测 **中位 2.7ms / 最差 6.5ms**，暂停时成员画面钉死 0ms 位移。
- BGM 只有房主：成员 `startSession(..., allowMusic=false)`；选曲试听、SMTC、任务栏进度同理。
- 开关：设置→系统→多人游玩 / `--party`；打开顺带允许多开（每个窗口登录不同用户）。
  只有一个人的房间 = 原来的单机流程，一行没改。
- 暂停只能房主按；多人下强制关掉"失焦自动暂停"；房主关窗后成员退回本地时钟。

### 两个真 bug（都是验证工具抓出来的）

1. **0 值时钟包**：房主还没发布时成员读到的 clock 字段全是 0，拿去算 → 误差几个小时，
   成员时钟直接跳到 +3993s，整首歌全 MISS。修：控制块加 `hostClockValid`，
   另外 `|error|>5s` 的包一律丢弃。
2. **音乐起播瞬间房主音频时钟跳一帧**（`AudioEngine::update` 里 `mMusicStartFrames = 现在`，
   30fps 下 25ms），恰好是第一批音符要判的时候，而 3% 的慢速修正要好几秒才吃完。
   修：起奏前自由对齐（只有开幕卡在看时钟），起奏后 3 秒内用 50% 速率修正。

### winsend 的三个坑（.workbuddy/tools/winsend.c 已修）

- SDL 的鼠标按键位置取自**系统光标**，不是 lParam → `click` 必须先 `ClientToScreen` +
  `SetCursorPos`。
- SDL 没有键盘焦点就**静默丢弃** `WM_KEYDOWN` → 要 `AttachThreadInput` 再
  `SetForegroundWindow`（单纯调用会被拒），必要时补 `WM_ACTIVATE`+`WM_SETFOCUS`。
- `ShowWindow(SW_RESTORE)` 的**还原动画**期间 `ClientToScreen` 是旧位置 → 点击偏上百像素；
  只在 `IsIconic()` 时还原，`place` 之后等 2s。
- 新动作：`focus` / `place x y` / `rect`；另外加了 gated 日志 `[ui] mouse down at x,y`，
  专门用来区分"事件没到"和"到了没命中"。

## 补一轮：用户实测反馈的四个问题（下午）

1. **"只允许一个实例"时禁用多人游玩 checkbox**：`ui::checkBox` 加了 `enabled` 参数
   （灰化 + `BeginDisabled` 吞点击；灰着时**不回写**，否则打开一次设置页就把开关关了）。
   选"只允许一个实例"会自动关掉多人游玩；档案加载时 `multiplayer==true` 则把 instanceMode
   抬成 1，保证文件自洽。
2. **昵称改了"用户"下拉框还显示默认用户**：下拉框列的是 `profiles/index.json` 的档案标签，
   昵称在档案数据里 —— 两个标签。现在改昵称即同步标签（空昵称不动），启动/切用户/多开换档案
   时也会自动纠正不一致的标签。已用用户自己的档案验证（日志
   `[profile] label of 'default' updated to 'xxt8582753'`）。
3. **"未成功触发多人模式"的真原因**：多人开关按**档案**存，房间按**机器**存。
   多开时第二个窗口会在实例策略判定**之后**换成另一个档案，于是它读到自己那份
   `multiplayer=false` → 不进房间 → 房主永远一个人。修法：进房间前 `PartyLink::roomExists()`
   试探本机有没有已开好的房间，有就**无条件加入**。已回归验证（B 不带 `--party` 也能进，
   日志 `[joined a room this profile has switched off]`）。顺带补了三条启动诊断日志，
   "多人没生效"看日志即可定位。
4. **触摸屏多窗口**：SDL 默认吞掉"点击激活窗口"的那一次按下
   （`SDL_MOUSE_FOCUS_CLICKTHROUGH` 默认 0）→ 后台窗口第一次触摸直接消失判废；
   多人模式启动时改成 "1"。触摸本身不抢焦点：Windows 按坐标把触点投给它下面的窗口。
   剩下的是层级问题（触摸会把窗口抬前台，重叠会互相盖住）→ 建议并排；
   需要的话再给从属窗口加 `WS_EX_NOACTIVATE`。

另外：`AppState::Party` 补了 `--screenshot-time` 触发（房主页以前拍不到，现在能截图核对 UI）；
截图看下来倒计时数字原来压在难度条上（挪到右列玩家区）、倒计时时队友显示"游玩中"
（改成起奏才变），两处都修了；左下角队友分数条实测正常（截图里显示 B 84 combo / 236906）。

`mp_verify.sh` 的偏差断言也改稳了：插值跨过"成员按设计追赶房主"的那一下会报出 350ms 假偏差，
现在 offset 变动 >20ms 的区间单独统计（`member clock corrections seen`）。当前：中位 2.5ms /
最差 7.0ms。两轮全 PASS。
