## 3. HaikuOS 移植评估 → `HAIKU-PORT.md`（同一提交）

- 可移植：`core/native`、`game/`（纯逻辑 + ImGui）、stb_truetype、PNG/MP3 资源。
- 四个真障碍：
  1. **miniaudio 没有 Haiku 后端**：`MA_HAIKU` 定义了但全代码只有 `MA_BEOS` 排除一处 pthread，
     后端清单里没有 Haiku。推荐 SDL 音频 + `ma_decoder` 自己混音。
  2. **GL 3.3 + 无 vsync**：Haiku 是 llvmpipe 软渲染；SDL2 的 Haiku 驱动
     `HAIKU_GL_SetSwapInterval` 直接 `SDL_Unsupported()`，只能自己 `SDL_Delay` 定帧；
     1080p 纯 CPU 光栅化性能是最大不确定项。
  3. `Party.cpp` 的 `CreateFileMapping`/`CreateEvent` → POSIX shm + sem（或直接砍多人）。
  4. `build.sh` 是 zig → windows-gnu；Haiku 要另写 `build-haiku.sh`（clang + HaikuPorts SDL2）。
- 顺带：`SystemMedia` / `NativeMenu` / `ShellIntegration` / `ChartDlGuide` 整块删或换
  BNotification / BMenuBar / BNodeInfo；`main.cpp` 45 处 `_WIN32` 守卫要逐块补。
- 结论：单机能玩 5~7 天，完整 2~3 周；建议独立 `haiku` 分支。想多平台的话 WASM/WebGL
  比 Haiku 现实（core 本来就是 emscripten 目标）。

## 4. seek 落点修正 + 进度条时间字体（提交 99402e0）

用户反馈："点进度条会自己跳到别的地方"。根因是我 0275c36 里时钟锚点算错：

- `songTime()` 是 **chart 时间**（chart 0 = 文件里的 `startPos`，官曲前约 9s 静音），
  我却用**文件位置**的帧数当锚点 → 每次 seek 都多走 `startPos`（日志实证：`seek 40s`
  之后 `clock now` 是 49 级别）。
- 第一版修正改成 `mMusicStartFrames = now - target*rate`，又踩第二个坑：帧计数是
  **无符号**、从 ma_engine 创建起算，target(40s) 比引擎运行时长(7s) 大 → 下溢被钳到 0，
  时钟读成 7.51s（日志实证）。
- 正解：`AudioEngine` 加 `double mMusicClipStartSec`（有符号偏移），
  `songTime() = mMusicClipStartSec + (now - mMusicStartFrames)/rate`；
  seek / resume 都 `mMusicStartFrames = now` + 设置偏移；新歌开始和 loadMusic 清零。
  验证：`CPSEKAI_SEEK_TEST=40` → `[seek-test] clock now 40.00s` ✅。

顺带：进度条上的时间文字原来用 `fg->AddText(ImVec2, col, text)`，那是 ImGui 默认
ProggyClean 点阵字；改成 `game::bodyFont()`（微软雅黑）+ `CalcTextSizeA` 量宽 +
半透明圆角胶囊底。无头截图开关 `CPSEKAI_SEEK_HOVER=1`（假悬停）。

⚠ 日志会混进用户自己那局的输出：测试时如果 `build/cppsekai.log` 里出现一串
`[seek] 37.53` 之类我没触发过的值，先看是不是他正开着游戏在拖进度条。

## 5. seek "响两声"（提交 9d73e3e）

一次点击会听到两声"咔"：press 时 `seekPlayback` 跳一次、release 又跳一次（同一位置附近），
每次 `ma_sound_seek_to_pcm_frame` + 重锚都是一次音频断点。改成：

- press 只置 `scrubActive` + `scrubTargetSec`（**不**真跳）；move 只更新目标；release 才跳。
  拖动期间进度条/旋钮跟着指针走，画面和音乐留在原位（没有实时预览，这是刻意的）。
- `seekPlayback` 去重：目标与 `songClock()` 差 < 50ms 直接返回（点在自己所在位置不出声）。
- `AudioEngine::seekTo` 跳完 `ma_sound_set_fade_in_milliseconds(&mMusic, 0, 1, 6)`
  （仅未暂停时）——seek 落在波形中间时第一帧满幅，就是那声爆音。
- 失焦/离开窗口时清 `scrubActive`，否则收不到抬起事件、下次移动会用旧目标跳一下。
- 回归：`grep -c "\[seek\]"` 应为 1。
