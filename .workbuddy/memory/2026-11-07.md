## 1. 演奏中拖动顶部进度条 = seek（已提交 0275c36）

- 三层一起跳，缺一层就出问题：
  - `AudioEngine::seekTo(chartSec)`：文件位置 = `chart + startPos + userOffset`，
    用 `mMusicStartFrames = now - frames` 重锚；暂停中改 `mPauseSongTime`；无 BGM 时
    `main.cpp` 拨 `perfStart`（墙钟）。
  - `JudgementEngine::seekTo(sec)`：落点**之前**的音符 `state=2` 静默消费（不判 MISS、
    不掉血、不计分），`mActiveHolds` / `mMissedHoldKeys` / `mHitEventIndices` /
    `mTailClaimed` 全清，`mStats` 归零、血量回初始。**`mWeightedNoteCount` 故意不重算**
    —— 跳过后半曲不该能打满分。
  - `core_api::clearHitNotes()`：核心的 `hitNoteIds` 不认时间，不清的话倒着拖回去音符已经"消失"。
- main.cpp：顶部 16px 命中带（条本身 3px 点不中），悬停加粗到 6px + 白钮 + `1:24 / 3:07`；
  鼠标/触摸的 DOWN/MOTION/UP 都在 `beginPointer()` **之前**被 `hudSeekPress/Move/Release` 吃掉；
  拖动时 ~90ms 节流真正 seek。多人游玩禁用（`party.active()`）。开屏卡期间不接。
- 无头验证：`CPSEKAI_SEEK_TEST=<秒>`。实测 `0001_expert` 跳 40s：
  `[audio] seek to 40.00s (file 49.00s)` / `[judge] seek to 40.00s (319 note(s) consumed silently,
  cursor 319/1040)` / `[stats] … miss=0 score=71996 combo=31`。**miss=0 是关键**（拖一下
  不该上百个 MISS）。

## 2. HUD / UI 原作对照 → `HUD-UI-AUDIT.md`（已提交 8dde2b4）

REA 继续挖，关键发现：

- **演奏 HUD 不是 Unity UI**：`ScoreView`(1219) / `LifeView`(1229) / `ComboView`(1235) 里
  每个节点是 `Transform + SpriteRenderer`，`ms_geom.py` 导出的 rect 全 0。
  **位置只能量 1920×1080 官方截图**，prefab 里没有。sprite 尺寸那层可比
  （`pixels_to_units=108`）。
- 结构缺三块：`ScoreSkill`（分数面板里的技能显示）、`LifeView.SkipButton`（跳过键在生命条内，
  我们独立）、`ComboView.APCombo/APEffectRoot`（AP 专用数字+字样）。
- 尺寸实锤：判定字官方 **324×96**，我们 310×81（高 84%）；评级字母官方 76×94，我们
  49×58×1.5 = 73.5×87。
- 控件（这些 prefab 有真 RectTransform）：复选框 `Base 72×74` / `Check 56×42`；开关
  `UIPartsToggle 180.8×100`（bg 152×56、旋钮 72、label 70×50）；滑杆 `560×24` + 手柄
  64×84 + Dot 48；标准按钮 `UIPartsCommonButton 336×96`、对话框按钮 408×116；
  对话框 `WindowRoot 1168` 宽、关闭 X 44×44 @ (-15,-15)、`DialogHeader` 高 100。
  **我们是网页复刻的紧凑尺度**（对话框 500/660/920 宽、按钮 ~125×35），整体约 0.43 倍 ——
  不是改常量能解决的。

  **sprite → 节点**的跨 collection 引用解析不了（`m_FileID>0` 没处理），拿到的是 collection hash。

## 3. HaikuOS 移植评估 → `HAIKU-PORT.md`（同一提交）

- 可移植：`core/native`、`game/`（纯逻辑 + ImGui）、stb_truetype、PNG/MP3 资源。
- 四个真障碍：
  1. **miniaudio 没有 Haiku 后端**：`MA_HAIKU` 定义了但全代码只有 `MA_BEOS` 排除一处 pthread，
     后端清单里没有 Haiku。推荐 SDL 音频 + `ma_decoder` 自己混音。
  2. **GL 3.3 + 无 vsync**：Haiku 是 llvmpipe 软渲染；SDL2 的 Haiku 驱动
     `HAIKU_GL_SetSwapInterval` 直接 `SDL_Unsupported()`，只能自己 `SDL_Delay` 定帧；
     1080p 纯 CPU 光栅化性能是最大不确定项。
  3. `Party.cpp` 的 `CreateFileMapping`/`CreateEvent` → POSIX shm + sem（或直接砍多人）。
  4. `build.sh` 是 zig → windows-gnu；Haiku 要另写 `build-haiku.sh`（clang + HaikuPorts SDL2）。
- 顺带：`SystemMedia` / `NativeMenu` / `ShellIntegration` / `ChartDlGuide` 整块删或换
  BNotification / BMenuBar / BNodeInfo；`main.cpp` 45 处 `_WIN32` 守卫要逐块补。
- 结论：单机能玩 5~7 天，完整 2~3 周；建议独立 `haiku` 分支。想多平台的话 WASM/WebGL
  比 Haiku 现实（core 本来就是 emscripten 目标）。
