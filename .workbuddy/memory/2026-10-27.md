## LIVE CLEAR / FULL COMBO / 三角尺寸（调查 + 改动）

用户要求：① 调查曲末 LIVE CLEAR 特效逻辑 ② 把 "LIVE FINISH" / FULL COMBO 显示按原作对齐
③ 点击 ripple 的三角大小对不上原作。

**结论（不是新发现，是把 2026-10-25 那轮的证据重新确认了一遍）**：
- **原作没有 "LIVE FINISH"**：`as_out` 里 `txt_liveclear_wh`(1220×166, LiveResultAtlas)、
  `txt_livefailed_wh`(1352×166)、`txt_liveresult_wh`(1272×166) 三张，没有任何 finish。
  曲末那 1.5167s 大字是 `fx_result_LiveClear`（**只在 clear 时播**）。
- FC / AP 是**结算页徽章**：`badge_result_fullcombo` / `badge_result_allperfect`（358×76,
  ResultAtlas），配 `clip_result_score_{fullcombo,allperfect}_v2_01`（2s，只动
  anchoredPosition.x 4.2→44.2 与 Color.a 0→1）。
- 我们的现状：只有 LIVE CLEAR banner；结算页**完全没有** FC/AP 提示，失败局也没有任何标记。

**改了什么**（⚠ 本回合**没有终端**（VS Code OOM 后 `run_in_terminal` 工具消失），
所以**没有编译验证**，只用 `get_errors` 确认无语法错）：
- `ResultData` 加 `failed / fullCombo / allPerfect`；`buildResultData` 从 stats 推
  （和写成绩同一套规则）；`--result-preview` 那套假数据之后重算一次，否则 miss=1 也显示 FC。
- `Renderer::loadHud` 注册 `result_badge_fullcombo` / `result_badge_allperfect` /
  `result_livefailed`（三张图本来就在 `assets/mmw/overlay/result/`，一直没用上）。
- `Result.cpp`：COMBO 右侧空带画徽章（滑动 40px + 淡入 2s）；失败局同位置画 LIVE FAILED。
  **`kBadgeCenterX/Y` 是临时值** —— prefab 的 RectTransform 这次没量到（AssetRipper 随终端一起没了）。
- `TapEffect.cpp`：`kShardScale` 从独立 0.60 改成 `= kRingScale`；三角 band 从裁过的 54~90
  回到实测 15.8~235.5（hold 42~147）；新增 `TriSpec::sizeBias`（单位随机取幂，tap hero 1.9 /
  hold hero 1.4）把分布压向小值 —— 平均值 ~41px（原来 ~43px），但跨度 7~106px。
  起因：原作用户反馈"三角大小不对"，而旧实现把 15 倍跨度裁成了 1.67 倍。
