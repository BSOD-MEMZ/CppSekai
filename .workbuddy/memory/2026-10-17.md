## 多人游玩三处收尾（commit b9d5985）

用户三条要求：① 删掉「再按一次确定强制开始」，必须全员确定；② 成员窗口不要禁用/遮盖
顶栏的工具，只禁列表，删「多人游玩 · 列表只读」标识和旁观按钮；③ 多人里跳过按钮像是没作用。

- **强制开始**：`main.cpp` 房主确定分支里的 `forcing = mpConfirmed && !allReady()` →
  `beginLoading()` 整段删掉，房主再按确定现在什么都不额外发生。状态行、房间胶囊提示里的
  「再按一次强制开始」一并改掉。
- **顶栏**：去掉 `drawSongSelect()` 里包住搜索/排序/刷新那段的 `BeginDisabled(partyReadOnly)`，
  以及画在顶栏上的那整块 banner（标识 + 旁观胶囊 + 状态行）。剩下的只读表达是列表的灰罩
  +「只读 · 由房主选曲」chip + `listHovered = !partyReadOnly` 那一道门。
- **搜索在成员窗口**：`filterOn` 不再排除 partyReadOnly；为了不让过滤把房主那首藏掉，
  把 `groupOf(lockedEntry)` 提到外面成 `lockedGroup`，过滤后 union 回 `visible`，
  并且**把 `lockedGroup` 加进 `listSignature`**（否则房主换曲时行缓存不刷新）。
- **旁观**：`mpSpectating` / `SelectPartyInfo::spectating` / `SelectPartyResult::spectate`
  全删；`allReady()` 的跳过语义只剩「座位在 PartySeatLobby = 没按确定/上轮坐掉」。
- **跳过按钮（真 bug）**：lead-in 是房间的，成员每帧被 `resolveSongClock` 拉到房主时钟，
  本地挪 `perfStart` / `audio.skipLeadIn()` 下一帧就被擦掉 → 看起来是按钮坏了。
  修法：`skipIntro()` 在 `party.active()` 时只 `party.requestSkip()`（往**自己座位**的
  `skipReq` 计数器 +1）；房主在演奏态每帧比 `skipTotal()`（全座位之和），**只认上涨**，
  涨了就 `performIntroSkip()` —— 房主时钟一跳全房跟着跳。开局时 `mpSkipSeen` 取基线，
  免得上一局的请求在新一局开头触发。共享块加 `skipReq`，**映射名升到 v3**。
- 回归脚本 `.workbuddy/tools/party_skip_check.sh`（两窗口 + `winsend` 点成员窗口的跳过钮，
  屏幕坐标 1280x720 下是 1222,42）。坑：PostMessage 点击要靠窗口拿到前台焦点，
  `SetForegroundWindow` 有时被系统拒 → 脚本里重复点几次，别指望一次中。
