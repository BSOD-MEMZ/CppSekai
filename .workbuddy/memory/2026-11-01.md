## 已修：LIVE CLEAR 的触发时机（commit 见下）

用户要求：**最后一个音符判完就出 LIVE CLEAR，不等 BGM 尾奏。**

根因：`trackDurationSec` 优先取 `audio.musicDurationSec()`（main.cpp:3124），是**音频**长度；
谱面几乎总比它早结束。

改法（`main.cpp`）：
- 新增 `constexpr double kLiveClearDelaySec = 1.6`（放在 `announceTrack` 上方，
  触发点和启动日志共用，别再各写一个 1.6）
- `effectiveEnd = resultAtSec > 0 ? resultAtSec
     : (chartEnd > 1.0 ? min(trackDurationSec - 0.15, chartEnd + kLiveClearDelaySec)
                       : trackDurationSec - 0.15)`
  其中 `chartEnd = core_api::getChartEndTimeSec()`（core 的 maxTicks）
- **`resultDue`（原 9667 行）也改成用同一个 `effectiveEnd`** —— 它原来自己又算了一遍
  `trackDurationSec - 0.15`，两处不同步会出现「banner 起来了但结算不切」
- 启动打 `[play] chart end ..s, track ..s (banner at ..s)`，banner 起来时再打
  `[play] LIVE CLEAR at ..s (...)`，一眼能看出是哪个 end 生效

**实测（0001_master，`--auto`）**：
```
[play] chart end 120.00s, track 123.23s (banner at 121.60s)
[play] LIVE CLEAR at 121.60s (chart end 120.00s, track 123.23s, trigger 121.60s)
```
改前触发点是 122.85s（= track-0.15），改后 121.60s。**这首测试曲只差 1.25s**（谱面几乎
和音乐一样长），所以肉眼差别小；谱面明显短于 BGM 的曲子会明显得多。
122s 截图确认 banner 正在屏上（`build/_lc2.png`）。

## 资源能不能挖全：能，但结算页的东西在一张 ASTC 图集里

`ScreenLayerFreeLiveResult` 引了 `sactx-0-2048x2048-ASTC 4x4-LiveResultAtlas`（**ASTC 4x4
压缩的 SpriteAtlas**）。直接用 AssetStudio 按 sprite 名导 `txt_liveresult_wh` **失败**
（只出了 `txt_liveresult_line_dgr`），但**导整张 atlas 是成功的**：

```
AssetStudioModCLI.dll <GameData 目录> -m export -t tex2d --filter-by-name "LiveResultAtlas"
→ sactx-0-2048x2048-ASTC 4x4-LiveResultAtlas-38a5d3ab.png (369KB, 2048x2048)
```

**这张图里结算页要的东西基本都有**（目视确认）：
`LIVE CLEAR!` / `RESULT` / `LIVE RESULT` / `LIVE FAILED...` 四组大字、评级字母 `C S A B D`、
判定标签 `PERFECT/GREAT/GOOD/BAD/MISS`、`+FULL COMBO!` / `+ALL PERFECT!`、
排名横幅 `1位~5位`、`MVP` / `SUPER STAR`、彩虹进度条、`イベントボーナス` 胶囊。

**注意：里面只有 `+FULL COMBO!` 这种小字，没有曲末那个大字** —— 印证 §8 的结论
（曲末 FC/AP 大字不在首包，和结算页是两回事）。

**所以「两段结算」是可做的**，前提是把 atlas 切好。第一段（summary）= LIVE RESULT 大字 +
进度条 + 事件徽章；第二段（score）= 评级字母 + 判定 + 分数（项目已有第二段）。
