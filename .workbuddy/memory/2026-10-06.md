# 2026-10-06

## 原生 Win32 菜单栏（设置 > 系统，默认关）— commit 4103628

用户需求：加一条 Win32 原生菜单栏代替游戏内部分操作按钮；默认保持现状。
拍板结果（AskUserQuestion）：① 菜单放 文件/视图/帮助 三组；② 启用后**隐藏**被接管的
顶栏按钮；③ 菜单展开时**自动暂停**（演奏中）。

### 实现
- `platform/NativeMenu.{hpp,cpp}`（build.sh 的 `platform/*.cpp` glob 覆盖，**不用改 build.sh**）：
  只负责搭菜单 + sync 勾选，命令 id 由 main.cpp 映射。`CheckMenuRadioItem` 画窗口模式
  单选点（逐个 CheckMenuItem 会画出三个勾）。
- `UserSettings::nativeMenuBar`，读写各一行（glassMode 旁边）。
- 挂载条件：设置开 && `windowMode==1` && `noFrameMode==0`。菜单栏画在**非客户区**：
  borderless=WS_POPUP 画不出、fullscreen 铺满、自绘无框把 NC 区交了出去。
  `SetMenu` 只动 NC 区 → 窗口外框不变、**客户区矮 20px**（实测 1000x600→1000x580），
  SDL 发 SIZE_CHANGED 自己重排，无需补偿。
- **菜单模态**：展开时 Windows 进自己的模态循环、SDL 泵停住（同拖窗口）。subclass 的
  `WM_ENTERMENULOOP` 置 `dragging=true` + 起 `kDragTimerId` 复用喂帧；`WM_EXITMENULOOP`
  收尾。**`WM_TIMER` 的"左键抬起=拖动结束"兜底必须 `!st->menuOpen` 才判** —— 菜单是
  点一下开、松开后还开着，照判会把定时器当场杀掉（实测 enter 后 drag frames 30，
  兜底被让开了）。
- `WM_COMMAND` 只记 id 进 `menuCommand` 信箱，主循环帧内消费 —— 喂帧是递归的
  （WM_TIMER→帧→泵→WM_COMMAND），不能在窗口过程里改游戏状态。
- 演奏中打开菜单 → `menuPauseWanted` → 帧内 `requestPause()`；演奏中 刷新/音乐商店
  置灰。结束所有实例 用 `MessageBoxW` 确认（原生外观；模态框嵌在喂帧里，`st->depth`
  挡住嵌套帧）。
- 选曲顶栏：`drawSongSelect` 加 `bool nativeMenuBar=false` 参数，开启时
  刷新/音乐商店/设置 不画，坐标从一个游标往后排（多人横幅右边界挂 guessX，自己跟着收窄）。
  main.cpp 传的是**设置值**而非"菜单现在真挂着"——避免切窗口模式时按钮跳来跳去。

- 独立目录（exe+assets+charts+userdata.json，**数据目录跟 exe 走**，不碰真档案）：
  windowed 挂上、客户区 -20px、外框不动；borderless / fullscreen 不挂；
  dump 显示全部菜单项 + 勾/单选点正确；send 109 勾翻转、send 102 真重扫、
  send 104 干净退出；演奏中 刷新/音乐商店 greyed。
- 截图对比：关=刷新/音乐商店/猜歌/设置 四颗；开=只剩猜歌。
- 菜单在**非客户区**，`--screenshot`（GL 帧）拍不到 → 新工具
  `.workbuddy/tools/menu_probe.py`（rect/dump/send <id>/menuloop enter|exit，
  从外面用 user32 查）。`menuloop enter` 是合成的，用来无头驱动喂帧分支。

### 坑 / 没验到的
- 一次运行里出现过 3 次没触发的 `WM_ENTERMENULOOP`（帧数 31/13/28 ≈ 1s/0.4s/0.85s），
  复跑 + CPSEKAI_MSG_LOG=1 都没复现 → 大概率是**用户真点了几下新菜单**；行为完全符合
  设计（喂帧 + 干净退出）。待用户确认。
- `glassMode 2`（自绘无框）分支在这台沙箱走不到：**无 Aero**（"[bg] Aero glass is not
  available"）→ glassMode 被强制回 0 → 菜单挂上是对的。门条件读的就是窗口过程用的
  同一个 `noFrameMode`，逻辑闭合，但真·无框下菜单被摘掉这件事没实测。
- 没验：菜单栏**实际观感**（DwmExtendFrameIntoClientArea(-1) 与 NC 菜单的合成效果）、
  演奏中开菜单真的暂停、结束所有实例的确认框、Win7。都要人看。
- AGENTS.md 新增「原生菜单栏」一节（在 多人游玩 之前）；顺手把 MEMORY.md 从 14KB
  压回 ~4KB（注入截断过）。

## Windows 融合度缺口审计（用户问"还能加什么"时 grep 出来的，截至今天全是 0 处）

- `SetThreadExecutionState` / `SDL_DisableScreenSaver`：**没有** → 挂着选曲磨蹭或
  AUTO 会撞上屏保/休眠。`SetThreadExecutionState` Win2000+ 就有，无版本坑。
- `SDL_DROPFILE` / `SDL_DropEvent`：**没有** → 谱面不能拖进窗口。
- `SDLK_AUDIO*` / `WM_APPCOMMAND` / 媒体键：**没有** → 报了 SMTC 但媒体键按了没反应。
- `ThumbBarAddButtons`（任务栏缩略图按钮）：**没有**。ITaskbarList3 的 vtable + GUID
  已经在 `platform/SystemMedia.cpp` 手写好（为进度条），加方法即可；点击走 WM_COMMAND，
  能跟菜单栏共用通道。
- `AppUserModelID`：**没设** → 任务栏分组/SMTC 归属靠 exe 路径猜，多开时可能粘一起。
- **窗口位置不持久化**：一律 `SDL_WINDOWPOS_CENTERED`（尺寸记了，位置没记）。
- 演奏中 `SDL_WINDOWEVENT_CLOSE` **直接 running=false**，Alt+F4 误触没有确认。
- `.sus` 文件关联 / Jump List / 托盘：都没有（托盘只有 chartdl 有）。

## 与 Windows 融合 批 A~D（用户"四批全要"）— commit 4c9c625 / f04ad4f / 3f6355e / 166fac9

按风险从低到高做，每批单独构建 + 验证 + commit。全部 `bash build.sh` 0 警告。
AGENTS.md 新增「与 Windows 的接缝」一节，四个批次的坑都记在那里。

**批 A（4c9c625）防屏保/休眠 + 拖放谱面 + 媒体键**
- `SetThreadExecutionState(ES_CONTINUOUS|ES_DISPLAY_REQUIRED|ES_SYSTEM_REQUIRED)`，
  最小化/退出放行，状态变了才调。实测 blocking→minimize→allowing→restore→blocking。
- `SDL_DROPFILE` 收 `.sus`（只在选曲界面生效），起奏复用「确定」那套收尾；
  事件块记得 `SDL_free`。新增 `--drop-test <路径> [秒]` 合成拖放（真实 WM_DROPFILES
  的 HDROP 属于"放"的进程，脚本驱动不了）。
- 媒体键：`SDLK_AUDIOPLAY` 演奏中=开关暂停卡、选曲=回车；`AUDIONEXT/PREV`=上下方向键；
  `AUDIOSTOP`=ESC。**SDL2 没有 AUDIOPAUSE/TOGGLEPLAYPAUSE**，合键落 AUDIOPLAY。
- **两个真 bug**：① `pulse()`/`pressed()` 原本定义在
  `if (pad != nullptr || !fakePad.empty())` **里面** → 没插手柄媒体键没人消费。
  把 `pulse` 提到那个 if 外面（抬起仍走 `padReleaseQueue` 延迟一帧，同帧 down+up
  会让 ImGui `DownDuration` 归零）。② `winsend.exe key` 的 lParam=0 → SDL 拿不到
  扫描码、事件被丢（连 F5 都不生效）。改成 `1|(MapVirtualKey<<16)`，媒体键再置扩展位。
- 新增 `CPSEKAI_KEY_LOG=1`（对标 `CPSEKAI_MSG_LOG`）。

**批 B（f04ad4f）窗口位置 + 标题曲名 + AUMID + 演奏中关窗确认**
- `windowX/windowY`：启动校验是否落在当前接的显示器上（`SDL_GetDisplayUsableBounds`），
  越界回落居中；跟着 `persistUserData` 走。实测往返精确（client 108,152 ↔ 窗口 100,120）。
- 标题演奏中改成 `CppSekai · 曲名 · 难度`，每帧调 `syncWindowTitle`（没变就 return）。
- `SetCurrentProcessExplicitAppUserModelID`（手写声明，shell32 已在链接行）。
  **副作用**：多开会并到一个任务栏按钮。
- **最大的坑**：SDL 把 `WM_CLOSE` 交给 `DefWindowProc`、**窗口当场销毁**（实测后面紧跟
  WM_DESTROY/NCDESTROY），想"先问一句"必须在窗口过程里吞掉它，
  用 `SDL_RegisterEvents` 的自定义事件通知主循环，`requestWindowClose()` 一处决策。
  实测：弹卡、重复请求忽略、**ESC=继续演出**（`eulaDialog` 只能被按钮关，ESC 得走
  `forcedChoice`）、结束所有实例（`cppsekaiForceQuitMessage()` 标记 + WM_CLOSE）不弹卡。

**批 C（3f6355e）任务栏缩略图按钮**
- 扩手写 vtable：`RegisterTab/UnregisterTab/SetTabOrder/SetTabActive/ThumbBarAddButtons/
  ThumbBarUpdateButtons`（COM 位置寻址，少一个后面全错位）。`THUMBBUTTON` 按 ABI 手写，
  走 `THB_ICON`+`hIcon`（省掉 IImageList）。
- 图标**现画**：`IconCanvas` 矩形/三角/粗线 → `CreateDIBSection(BGRA)` →
  `CreateIconIndirect`，颜色按 alpha 预乘。五个（暂停/继续/有声/静音/返回）。
- 三按钮：暂停·继续 / 静音（`userMuted`，跟"最小化静音"并列） / 返回选曲。
  点击走 `WM_COMMAND`（`HIWORD==THBN_CLICKED==0x1800`）→ 跟菜单栏同一条挂起命令通道
  （缩略图 1..3、菜单 101+ 不重叠）。**「灰掉」只是 UI，处理端要另挡一道**（实测踩到）。
- 返回选曲 = 置 `escapePressed` → 消费块被挪到 ESC 分支**之前**（同帧生效）。
- 顺手修 `menu_probe.py`：`tasklist` 输出中文系统是 GBK，按 UTF-8 解会炸，改显式 encoding。
