# 2026-09-19

## 09:00-09:40 两件用户需求：多人开局倒计时删掉 + 失血阴影几何修好

用户原话：「去掉游戏开始的那个倒计时，失血阴影的显示也有问题」。问了一句确认，
倒计时指的是**多人房间里「即将开始 5.8s」那个大数字**（单机开局本来就没有倒计时，
截图 `--screenshot-time -0.5` 确认过：只有舞台淡入）。

### 1) 多人开局不再有倒计时（改成"加载完就开"）

**旧行为**：房主一开始就把起奏时刻定成 `now + 5.8s`（`beginCharging`），全房在那干等
5.8 秒，选曲界面上盖一层 + 中央大数字倒计时。**实测等待固定 5.8s，跟加载快不快无关。**

**新行为**（charge 分两段，靠 `startCounter == 0` 区分）：
- 加载段：房主 `beginLoading()`（epoch++、phase=Charging、**不写 startCounter**）；
  每个窗口加载完自己的谱面 `setSeat(PartySeatLoaded)`（新加的座位状态）。
- 武装段：房主 `allLoaded()`（非 Lobby 座位全是 Loaded）→ `armStart(now + 0.8s)`
  （**不动 epoch**，否则成员以为换了一轮）。
- 看门狗 `kPartyLoadTimeoutSec = 6.0`：有人卡住/加载失败时照常武装，不会整房停死。
- 房主强制开始（第二次按确定）也走 `beginLoading()`：没确认的窗口立刻退成 Lobby 让开。
- 删掉选曲界面上的遮罩 + 大数字；面板状态行只写 `谱面加载中…` → `即将开始`（不带数字）。
- 房主自己加载失败时 `releaseSong()` 回大厅，成员按"房主已放弃本曲"回列表（原来会停死）。

**实测**：`[party] start in 0.80s (every chart loaded; the room waited 0.24s for the loads)`
—— smoke 谱加载 0.2s，总等待 ≈1.0s，比旧版省约 4.8s。
回归：`bash .workbuddy/tools/mp_verify.sh` **三轮全 PASS**（同一 start counter / 时钟偏差
中位 3.3ms 最差 6.4ms / 暂停冻结 0ms / 结算与重开房间），另跑了"房里只有一人"路径。

**坑（记在 AGENTS.md 了）**：
- 成员第一次看到 charge 时的 `late` 判定必须带 `startCounter != 0`。QPC 是个大正数，
  裸写 `now >= startCounter` 会在加载段把所有窗口判成"错过开局"。
- `armStart` 只在 `phase == PartyCharging` 时写，否则会把已释放的房间复活；
  房主侧 `mpArmedEpoch` 保证一轮只武装一次（重复武装会把时刻一直往后推）。
- **帧时钟不能用来量加载耗时**：加载在某一帧里同步发生，`uiClock` 那一帧不推进，
  量出来是 0.03s。改用 QPC（`counterToSeconds`）才是真时间。
- 迟到的窗口仍然正确入局（时钟锚在共享 QPC 上，只是少看一段开幕卡），不用额外踢人。

### 2) 失血阴影（damage vignette）几何修好

**旧实现**：四角各一块 `min(w,h)*0.55` 的方块。16:9 上 `2*0.55h = 1188 < 1920`，
于是**上下边缘正中留了约 880px 的亮带完全没被压暗**，且方块边界处 50% 黑 → 0 是硬断崖。
实测（1920x1080，`CPSEKAI_VIGNETTE=0.85`）：y=8 一行上 alpha 127 在 x=594、0 在 x=614。

**新实现**：**四条整边条**，各自垂直自己那条边渐隐，四角两条叠加自然变最暗。
`rc = min(w,h)*0.42`，单条峰值 `120*damageVig`（角落 ≈1.6 倍）。
实测：上/下边缘中段 alpha ≈92（原来 0），四角 ≈134，屏幕中心 0，且逐像素扫无断崖。

**注意 `ImDrawList::AddRectFilledMultiColor` 的四个角顺序是
（左上、右上、**右下**、左下）**——下边两个不是阅读顺序。旧代码注释写错了顺序，
但因为只用了对角两个顶点，效果侥幸是对的。新代码要按真顺序传。

**新增调试探针**：环境变量 `CPSEKAI_VIGNETTE=<0..1>` 把阴影冻结在这个强度上，
掉血需要真人漏接、`--screenshot` 造不出来（`--test-hits` 是"帮打"，life 不掉）。
对照图手法：同一时刻跑 `=0` 与 `=0.85` 两张，用 PIL 按 `1 - vig/zero` 反算 alpha 分布。
已写进 CLI.md 第五节。对比图：`build/shots/vig_compare.png`。

### 验证手法
- 截图量 UI 一律用 `--screenshot`（GL glReadPixels，方向无歧义）；
  **同一时刻两次运行的画面会有 1 帧级差异**（音符/特效位置），逐像素比 alpha 时要把
  明显外点当噪声，别把噪声当断崖。
- `--screenshot-time` 可以给**负数**（谱面时间为负 = lead-in 期间），用来截开场过程。
