### 四个不踩第二次的坑
1. **`if (tab == N)` 链的最后一个分支原本是裸 `else`**（账户）。往后面接新页签要先把它改成
   `else if (tab == 4)`，否则编译报 `expected expression`。
2. **`eulaAlive` / `eulaDismissedThisRun` / `eulaPadChoice` 被提到了 `drawSettingsCard` 之前**
   —— 否则那颗按钮够不着它们（lambda 定义点之后声明的名字不可见）。按钮里要同时
   `eulaDismissedThisRun = false`，不然第二次按就没反应（那个标志是"这次运行关过了"）。
3. **页签内容的可用宽度是"卡片宽 − padX"**：child 有卡片那么宽，而文字从 `padX` 起排，
   超出的部分直接被裁（「账户」页那两行一直是这样，至今没人管）。所以「关于」页的长行
   要么短、要么用 `PushTextWrapPos(x + 330*s)` 显式钉住换行宽度 —— 光靠 `TextWrapped`
   会按 *child*（=卡片）宽度换行，直接顶出卡片。
4. **无头截设置卡时，首启那张 ELUA 会盖住它**（两张都是独立窗口，ELUA 后画、在正中）。
   `ui::scale()` 只看高度（`h/860`），所以把窗口开**宽**（`--width 2600 --height 900`）
   就能让 ELUA 落到屏幕中间偏右、设置卡留在左上角，互不遮挡 —— 这招对以后截任何卡片都好使。

## 两个通用坑（这轮踩到的，已写进 AGENTS.md）

1. **用户自己在开着游戏时做无头验证**：运行的 exe 会让链接报 `Permission denied`，
   实例互斥体又会把下一次无头跑挡掉。解法是两条一起用：
   `OUT=build/probe.exe bash build.sh`（build.sh 新加了 `OUT=` 覆盖）
   \+ `./build/probe.exe --instance multi ...`（另占一份 Profile 锁，**不会**加入他的房间，
   但会挑到另一个档案）。
2. **"刚跑完的构建 0 警告"可能是假的**：zig 有全局对象缓存，命令行不变就一个 TU 都不重编，
   `warning:` 自然是 0。用 `bash build.sh -DCPSEKAI_FORCE_REBUILD=1` 打掉缓存才是真·冷编译
   —— 于是发现 `platform/FontOutline.cpp` include 的 `imstb_truetype.h` 一直漏着 **30 条
   `-Wunused-function`**（它是我们的 TU，`-w` 管不到）。已在 include 处用
   `#pragma clang diagnostic ignored "-Wunused-function"` 包住，冷编译现在真的是 0。

## SMTC 封面（put_Thumbnail）终于真的能传了（17:3x~18:0x）

**根因**：`RandomAccessStreamReference::CreateFromUri` 的文档只接受
ms-appx / ms-appdata / http / https 四种 scheme，**file:// 不在其中**，但它对 file:// 照样
返回 S_OK（它根本不碰文件）—— 于是 `put_Thumbnail hr=0x00000000` + 日志"cover -> ok"
全是**假的成功**，媒体浮层一直空白。所以"修过一次还是没封面"不是修错，是这条路本身不通。

**改成**：`InMemoryRandomAccessStream`（RoActivateInstance）→ `Buffer`
（IBufferFactory::Create）→ `IBufferByteAccess`（纯 COM，IID 905A0FEF…，winmd 里查不到，
和 IBuffer 的 905A0FE0 只差一位）memcpy 字节进去 → `GetOutputStreamAt(0)` +
`IOutputStream::WriteAsync` → `Seek(0)` + `get_Size()` 校验 → `CreateFromStream`。
`fileUriFromPath` / `IUriRuntimeClassFactory` 那套已删。

**踩到的三个坑**（细节都写进 AGENTS.md 了）：
1. `winmd_dump.py` 把 `IDataWriter` 打成了 27 行（`WriteBuffer` 重复），照抄导致槽位后移：
   `StoreAsync` 落到 `FlushAsync`（照样返回状态正常的 op，看不出问题）、`DetachStream`
   落到 vtable 之外 → **无栈段错误**。已给脚本加了重复名警告。
2. `WriteAsync` 的 `IAsyncOperation` **永远停在 Started**（PeekMessage 和
   CoWaitForMultipleHandles 都推不动），`Cancel()` / `Release()` 各崩一次。
   但数据是**同步写进流的** —— 判成败只能看流自己的 `get_Size()`，op 指针故意丢掉不管。
3. 别用 `DataWriter` 绕：它持有流，`Release` 会关流，`DetachStream` 拿的是"归属引用"，
   两种收尾都实测出过 stream 被提前销毁的崩溃。

**验证**：`--no-party --sus charts/0001_master.sus --auto`，日志
`[media] cover -> ok (charts\0001.png; 971161 bytes in, stream size 971161)`，
`--test-restart` 换曲重设封面也不崩。**封面在系统媒体卡片里是否可见需要人眼确认**
（GSMTC 的 MediaProperties 不暴露缩略图，程序测不了）。
