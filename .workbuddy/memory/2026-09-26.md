### 核查结果（按证据强度）

**A. 根因已定位的真 bug**

1. **输入法候选框不显示（建议 4）** —— 全仓**没有任何 `SDL_StartTextInput()` 调用**。
   - 只有 `main.cpp:1303-1306` 设了 `SDL_HINT_IME_SHOW_UI=1` / `SDL_HINT_IME_INTERNAL_EDITING=0`。
   - `third_party/imgui/imgui_impl_sdl2.cpp` 是 **1.92.5** 版；其变更日志 line 50 明确写着
     2023-04-06 起**移除了** `SDL_StartTextInput()/SDL_StopTextInput()` 的调用，现在只留
     `ImGui_ImplSDL2_PlatformSetImeData()` → 在 `WantVisible` 时调 `SDL_SetTextInputRect()`。
   - 而 SDL2 里 `SDL_SetTextInputRect()` 受 `SDL_IsTextInputActive()` 门控 → 没 StartTextInput
     就是空操作 → IME 组合窗位置从不更新 → 全屏下候选框跑到屏幕外/不显示。
   - **修法**（常规做法，改动小）：`io.WantTextInput` 的上升沿 `SDL_StartTextInput()`、下降沿
     `SDL_StopTextInput()`，rect 由 ImGui 后端自动喂。要注意与现有 `typingText` 守卫（F/H/F5 热键）共存。

2. **启动扫描期窗口无响应（建议 6）** —— 已用本机日志坐实时间线。
   - `cppsekai.log`：`[boot] fonts 442.0 ms` → `[boot] chart scan 486.8 ms`（本机 65 张，44ms）。
   - 但 `drawSplash(1.0f, "ready")` 在 **main.cpp:2254**，`scanAllChartDirs()` 在 **main.cpp:2336**
     —— **进度条走满之后**才开始同步扫描，扫描期间没有任何帧、没有消息泵 → Windows 判定未响应。
   - 谱面多 / 磁盘慢时这段是线性的（注释里记过 700 张 ≈ 1.3s 的旧数据，那次是二次扫描）。
   - **修法**：把扫描挪到 `drawSplash(0.92f,"loading audio")` 前后，或改成每 N 个谱面刷一帧 + 进度条。

**B. 真需求（要动结构）**

3. **自定义键位（建议 1）** —— `main.cpp:293` 的 `kLaneKeys[12]` 是硬编码常量
   （`SDLK_z s x d c v g b h n j m` → 12 lane，`keyLanePos = lane - 5.5`）。
   `KEYDOWN`(main.cpp:5493) / `KEYUP`(5517) 直接查这个数组；hold 的松手判定靠 `keyHeld[]`。
   - 改动面：数组变可配置 + 设置页 + 冲突检测 + 存取；**还要避开 F / H / F5 / SPACE / ESC 这些全局热键**。
   - 顺带事实：**键盘无法产生左右 flick**（代码注释明说，left/right 必须鼠标/触摸），
     手柄目前只能导航 UI（`padDown` 只喂 ImGui 焦点环），**不能打歌**。自定义映射如果含手柄＝新功能。

4. **界面太小 / 中间过空（建议 3.2 + 截图）** —— 有具体数字：
   - 选曲布局 `SongSelect.cpp:2764-2766`：`listX = 150k`、`listW = 450k`（1920 宽下列表占 150~600）。
     右侧手机面板 `phoneX = w - phoneW - 30k`，phoneW 上限 `w*0.46` → 1920 下约从 x=1005 起。
     **中间约 400px 是纯空的**，截图批注"中间过空"属实。
   - 头部那一行 `headerRowH = 33k`（2869 行）＝ 1080p 下 33px 高，确实偏小。
   - 缩放旋钮在 设置→画面→界面缩放（70%~150%，main.cpp:3471），会乘进 `k`（`kBase=clamp(h/1080,0.5,2)`，
     `k=kBase*scale`）—— 所以他说的"还调不了"其实是**没找到**，不是不能调。

5. **账户 / 存档页交互（建议 5）** —— 位于 main.cpp:4020 起（设置→账户）。
   现状：用户下拉选择 + 新建 + 两段式删除（先 arm 再确认）+ 导入/导出走原生文件框。
   问题在于信息层级："存档"这个词在音游语境指成绩，而本作成绩是自动保存的，玩家点进来看到的是
   用户管理，预期错位。属于**重排 UI + 补确认/撤销**，不动数据层。

6. **内置说明（建议 8）** —— README 131 行 / CLI.md / SETUP.md 都在，游戏内为零。与建议 7 是同一件事。

**C. 结论需要修正的两条**

7. **"加入退出等实体按键"（建议 7）—— 功能已经有了。** `main.cpp:5799`：ESC 在
   Select / Result 直接回列表或 `running = false` 退出，演奏中则开暂停框。

**D. 需要先取证（现阶段不该猜着改）**

### 补充：他的机器是 Celeron N3450 —— 三条症状要重新定性

Intel 官方 + CPU-Monkey 查证（2026-09-26）：Apollo Lake，Q3'16，4C/4T，**基频 1.10 GHz**
（burst 2.20 GHz，**无 Turbo Boost 技术**），6W TDP / 4W SDP，内存上限 **8 GB**，
PassMark ~1850、GB5 单核 281 / 多核 923。
GPU **Intel HD Graphics 500：12 EU**，200–700 MHz，Gen9，**FP32 仅 134 GFLOPS**
（≈2007 年独显水平），Cinebench R11.5 iGPU OpenGL 25.2 fps。

- **"闪屏+卡顿"主要是硬件**，不是 bug：`Renderer.cpp:355-357` 是
  `glDisable(GL_DEPTH_TEST)` + 全局 `glEnable(GL_BLEND)`，即**纯 overdraw**（无剔除、逐像素 alpha 混合），
  这套在 12 EU 上必然撞填充率。而且跑不到 60 帧时 vsync 会量化到 30/15，看起来就是"一跳一跳"。
- **"键盘不灵敏"要改判**：判定在 `SDL_PollEvent` 里一帧一次（main.cpp:5493），
  **输入延迟 ≈ 一帧时间**。他若跑 20 fps，平均 25 ms、最坏 50 ms —— 远大于我上一轮猜的
  音频时钟超前（一个输出缓冲，10~30 ms）。低帧率是主要矛盾，时钟是次要项。
- **"扫描无响应"是硬件放大版**：这类机器多为 eMMC（随机 IO 极差）+ 弱 CPU。
  代码那处"进度条走满才扫"依然该修，且**对他价值更大**。

### 新发现：小屏上 UI 会缩到 0.71（这才是"按钮太小"的真因）

`SongSelect.cpp:2543-2545`：`kBase = clamp(h/1080, 0.5, 2.0)`，`k = kBase * uiScale`。
**在 1366x768 这类小屏笔记本上 kBase ≈ 0.711** → 选曲头部 `headerRowH = 33k` **实际只有 23.5 px**。

→ 结论修正：不是"设计尺寸偏小"，而是**小屏下限过低 + 缩放上限不够**。
（待确认他的屏幕分辨率；N3450 机器常见 1366x768。）

## 第二轮：修「勾了没感觉」+ 补粒子树剪枝 + 输入法闪屏

### 弱化特效的真根因（我第一版做错了，用户实测打脸）
`initializeEffects()` 里有一句 `gRuntime.effectView = {}`，而它**每次加载谱面都会跑**
（`finishLoadedScore()`）。我把开关放在 `EffectView::simpleEffect` 成员上 → **选曲界面勾得好好的、
一进歌就被清成 false** → 玩家看到的是全量特效。这就是「我勾了但完全不觉得被简化」。
真值改放 `PreviewRuntimeConfig::simpleEffect`，`initializeEffects()` 在 `= {}` 之后立刻补回去。
⚠️ **以后往 `EffectView` 加任何"设置类"状态，先确认它会不会被这一句冲掉。**

### 补上「粒子树剪枝」（用户要的其实是这一层）
用户原话「一堆雪碧图拼起来的特效中只保留比较基础的那一层」指的是**单个特效内部**的层，不是
EffectType 之间 —— 我第一版只做了后者，所以 tap 命中时那团粒子原封不动。
现在 `createEmitterFromParticle(id, simple)` 在简化时**不建 children**：一个 note 特效是
「根 + Ripple + 两组飞散粒子 + 两个方形碎片」拼成的树，砍到只剩根 = 那张基础贴图。
切换时 `setSimpleEffect` 自己 `init()` 重建粒子树（树是按开关建好的）。

### 我上一轮的验证不干净（教训）
靠"profile 文件里出现了 `simpleEffects` 这个键"就当成状态对了，结果**两次跑的是同一个状态**，
对照整个作废。现在流程改成：**显式写值 + 读回打印 + 日志断言**（`[core] effects ready (simple=N)`
是新增的诊断口，排查"开关没生效"先看它）。另外实测确认：**`--screenshot` 跑完
`profiles/<id>.json` 会被写回**（键会新增），测试值必须手动恢复。

### 输入法「每次输入整屏闪一下」—— 两处推测性修复，待人工验证
1. `syncWindowTitle()` **无条件**调 `SDL_SetWindowTitle`（→`SetWindowTextW`），而账户页每敲一个
   字符都会调它；无边框 + DWM 扩展框架窗口上大概率就是那"闪一下"。已改成标题真变化才设。
   **这大概不是 IME 改动引入的**，只是以前输入法不能用、没人真在输入框里打过字。
2. ImGui 每帧喂 `Platform_SetImeDataFn` → SDL 每帧 `ImmSetCompositionWindow`；已在 main.cpp 用
   `setImeRectOnChange` 覆盖后端的 sink，只在 rect 真移动时才转发。
**若仍闪**，二分：英文输入是否也闪 / 窗口模式（非全屏）是否也闪 / 搜索框 vs 账户页昵称框。

## 第三轮：右键/长按、收藏夹、自定义键位、左下角帧率、键盘灵敏度

用户一次提了 4 件事，都做了。细节写进 AGENTS.md 新增的「右键 / 触摸长按 / 自定义键位 /
帧率显示」一节，这里只留结论和踩到的坑：

- **键盘灵敏度（真因）**：判定原本读 `songClock()`，也就是"主循环轮到这一帧的时刻" ——
  按键先排进 SDL 事件队列，下一次 `PollEvent` 才被看到，低帧率下这一等十几到几十毫秒
  全被算成"你按晚了"。改成 `songTimeAtEvent(eventMs)` 按事件时间戳回推，
  键盘 / 指针按下 / flick 移动三处一起改。**这比之前猜的"音频时钟超前"直接得多。**
- **收藏夹**：按 musicId 存 `settings.favoriteMusicIds`，右键 / 长按切换，分组加「按收藏」。
  坑：`loadUserData()` 里 `std::clamp(settings.groupMode, 0, 3)` **写死** → 第 4 档被咬回 3，
  表现就是"设了按收藏但下拉显示按首字"。已改成 `kSelectGroupCount - 1`（单一出处）。
- **自定义键位**：`settings.laneKeys[12]`，UI 在 设置 → 演奏 → 按键映射（3 列 × 4 行），
  新键与已占用的 lane 直接对调；等键状态 `rebindLane` 在 KEYDOWN 开头吞掉按键。
- **左下角帧率**：画在 (24, 1080-26)（多人分数条占 1080-24 往上，底下那 24px 空着），
  0.25 s 采一次。⚠️ **我从截图里把 "60.0 fps" 读成了 "0.0 fps"**（10px 字号），
  白查了一轮 —— 所以加了 `[fps]` 截图日志，以后数字类显示别靠读图。
