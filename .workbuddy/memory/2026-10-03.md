### 关键发现：原作几乎没有 hover

全表 `:hover` 只有 `.picker-item:hover { transform: scale(1.5) }`（选图弹层），
按钮 / select / checkbox / input **一条都没有**。实测验证：hover 薄荷按钮后
`getComputedStyle` 的 `background-color` 仍是 `rgb(119,238,221)`，`box-shadow`
不变。唯一的指针反馈是 `cursor: pointer`。

改的是 **`:active`（按下）**，而且是"反白"：

| 控件 | 静止 | 按下 |
|---|---|---|
| btn-blue/btn-pink | #77eedd / #444466 | **#e3fcf8 底 + #77eddd 字** |
| btn-white | #ffffff / #444466 | **#a1f4ec 底 + #ffffff 字** |
| btn-red | #ff2b2b / #fff | #000000 底 + #fff 字 |

`transform: none`、`opacity: 1`、box-shadow 不变 —— **没有位移/缩放**。
全局 `* { transition: all 0.2s }`（第 1191 行），所以连按下反白也是 0.2s 缓动。

### 规格（实测，非目测）

- 调色板：文字 **#444466**（全站唯一文字色，h1-h3/p/label/i/button/select 都是它）；
  卡片/侧栏/窗口底 **#ebebf2**；薄荷 **#77eedd**；粉按钮 #ff5599；**对勾粉 #ff77ac**；
  红 #ff2b2b；橙 #ffbb00；青字 #00ccbb；分隔线 **3px #d1d1d1**。
- 阴影：**`0 0 8px rgba(68,68,102,.5)`** —— 零偏移、8px 模糊、颜色就是文字那个
  #444466 的半透明。**勾选框是 4px 版**（`0 0 4px`）。所以观感是「四周一圈均匀灰晕」
  而不是我们的「向下投的硬影」。
- 圆角阶梯：pill(r=h/2) = 按钮 30/60、圆按钮、**select**；20px = `.window` 卡片；
  **10px = 文本输入框/textarea/勾选框**；50% = 单选。**注意 input 不是 pill，
  select 才是** —— 这条容易搞反。
- 尺寸比例：按钮 `padding 8px 50px`、`min 200x60`、`font-size 20px`
  → **控件高 = 3.0 × 字号**；select 同 60 高、`padding 10px 20px`（右 50px 留给箭头）、
  `min-height 60px`。勾选框 40px 对 20px 标签 = **2.0×**；单选 35 盘 / 25 点。
- select 箭头是内联 SVG `M7 9l5 8 5-8z` 实心三角（10x8 的 viewBox 25x25，
  `background-position: 100% 50%`），**静态不旋转**。select 的下拉列表是系统原生的，
  原作没有任何弹层样式。
- range：轨道 **5px 实心薄荷**（不是"已播放段"双色），滑块 20px 白圆，禁用轨道
  `rgba(20,159,138,.333)`。
- 禁用：按钮 **`opacity: .5`**（不是换填充色）；select `background: #ebebf2; cursor: progress`。
- `.window` 入场 `scale(0%) → scale(100%)`，**0.1s linear**；没有 box-shadow。
  背景 dim 是 `rgba(0,0,0,.733)`（我们 09-19 主动去掉过，别顺手加回来）。

## 阴影晕返工（提交 ee9e2e2）—— 教训：别用"看起来差不多"糊阴影

第一版 halo 做成「五层各 0.085、每层外扩 1.6*s」，用户一眼看出「阴影大得诡异」。
去原作自己的渲染上量了一下真实衰减（薄荷按钮边缘向外扫，背景 #ebebf2）：

    1px -31/255 (a=0.19)   4px -13 (0.078)   7px -4 (0.024)
    2px -23    (a=0.14)    5px  -9 (0.054)   9px -2 (0.012)
    3px -18    (a=0.11)    6px  -6 (0.036)  11px  0

**CSS 的 `0 0 8px rgba(68,68,102,.5)` 到边缘只剩 0.19** —— 模糊会把浓度摊掉，
字面上的 0.5 完全不是边缘值。我第一版在 6px 处还有 0.24，是原作的 **6.7 倍**，
而且每层等浓度导致整条带子又厚又匀 → 观感就是一团灰，不是一道边。

改法：同心环**由外向内每层翻倍**（a,2a,4a,8a,16a，最内 0.100），外扩 `kShadowReach`
从 8*s 收到 7*s。参数 `int layers` → `float spreadScale`（勾选框 0.5，因为原作
那一处是 4px 模糊而别处 8px）。复量我们的渲染：1px -30 / 2px -24 / 4px -10 / 6px -4，
与原作基本重合。

**新工具 `.workbuddy/tools/png_scanline.py`**：打印 PNG 某一行扫描线的 RGB + 相对
首像素的差值，专门用来量阴影/边缘衰减。**扫描起点必须在阴影已经归零的地方**（离开
控件 ~30px），否则差值是相对一个已经被压暗的像素算的，整条曲线会被低估。
算 alpha：`d = a * (阴影通道 - 背景通道)`，navy #444466 压在 #ebebf2 上的除数
是 R/G 通道的 167（所以 d=-30 ≈ a 0.18）。
