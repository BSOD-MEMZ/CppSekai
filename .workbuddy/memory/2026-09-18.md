# 2026-09-18

## 判定窗口可配 Bad / Miss / 长条容错（commit `99f9598`）

诉求：设置里的判定窗口原来只有 Perfect/Great/Good 三根滑杆，Bad 和 Miss 的边界写死。

改法：
- `JudgementWindows` 加 `holdTailGraceMs` / `holdStartGraceMs`，把 `Judgement.cpp`
  里写死的 `kHoldGraceSec` (0.18) / `kHoldStartGraceSec` (0.14) 换掉。这两个常量
  现在没了，改长条容错只动 `JudgementWindows`。
- `UserSettings` 加 `badMs` / `missMs` / `linkBadMiss` / `holdTailGraceMs` /
  `holdStartGraceMs`。注意 `badMs` 和 `missAfterMs` 是**两个**概念：前者是迟按还能
  算 BAD 的边界，后者是没人碰的音符自动 MISS 的时刻；`linkBadMiss` 勾上时后者=前者
  （就是老行为 `goodMs + 60` 的意思，只不过现在跟着 badMs 走）。
- 老档迁移的坑：`profiles/*.json` 里没有 `badMs`/`missMs` 键。读的时候**不能**用
  `s.value("badMs", settings.badMs)`（会回落到结构体默认、把老档手感改紧），要用
  `-1` 当哨兵再按 `goodMs + 60` 推。`UserSettings` 的默认值也取 200 保持新档一致。
- 启动多打一行 `[settings] windows perfect=.. bad=.. missAfter=.. holdTail=..
  linked=..`（`main.cpp` 判定设置生效块里），调试判定手感先看它。
- 设置卡片 380x700 → 380x780（判定页多了行）。

顺带补的组件能力（`game/Ui.*`）：
- `slider` / `checkBox` 加 `enabled=false`：画灰 + `ImGui::BeginDisabled()` 吞点击，
  **灰着时绝不回写值**（否则打开一次设置页就把值悄悄改掉）。判定页用它做
  「Bad 与 Miss 同步」时的 Miss 滑杆。
- `stepper` 加 pick-one 档：`presets.size() == deltas.size()` 时把 `*value` 当
  "选中第几项"（`-1` = 没选中，pill 显示 `--`），每个胶囊就是它自己那一项、按一下
  选它（**不是**按 delta 加减——第一版写成加减了，点一下直接掉到 -1）。胶囊宽度按
  `rowW` 和最长标签现算，否则三个中文标签会顶出卡片右边。
- 长条容错三档预览：宽容 180/140（原值）/ 较紧 120/80 / 严格 60/40；下面的滑杆
  拖到别的值就 `holdPreset = -1`（不再高亮预览）。

验证手法（这次踩到的坑）：`--screenshot` 出来的 PNG **是帧缓冲尺寸、和窗口不一定
一样**（本次 1280x720 的窗口出的是 900x520 的图，x/y 缩放系数还不相等），所以拿
PNG 像素坐标当客户区坐标去点会偏。要确认 UI 行为，靠日志比靠像素稳：
`[settings] windows ...` 一行就能验完读取路径；手写一个带
`badMs=250 missMs=310 linkBadMiss=false holdTail=90 holdStart=60` 的 profile 跑一次，
读回一模一样，就说明 JSON 键名和 clamp 都对了。
