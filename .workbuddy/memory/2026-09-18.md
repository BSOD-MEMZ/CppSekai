## 判定窗口可配 Bad / Miss / 长条容错（commit `99f9598`）

诉求：设置里的判定窗口原来只有 Perfect/Great/Good 三根滑杆，Bad 和 Miss 的边界写死。

改法：
- `JudgementWindows` 加 `holdTailGraceMs` / `holdStartGraceMs`，把 `Judgement.cpp`
  里写死的 `kHoldGraceSec` (0.18) / `kHoldStartGraceSec` (0.14) 换掉。这两个常量
  现在没了，改长条容错只动 `JudgementWindows`。
- `UserSettings` 加 `badMs` / `missMs` / `linkBadMiss` / `holdTailGraceMs` /
  `holdStartGraceMs`。注意 `badMs` 和 `missAfterMs` 是**两个**概念：前者是迟按还能
  算 BAD 的边界，后者是没人碰的音符自动 MISS 的时刻；`linkBadMiss` 勾上时后者=前者
  （就是老行为 `goodMs + 60` 的意思，只不过现在跟着 badMs 走）。
- 老档迁移的坑：`profiles/*.json` 里没有 `badMs`/`missMs` 键。读的时候**不能**用
  `s.value("badMs", settings.badMs)`（会回落到结构体默认、把老档手感改紧），要用
  `-1` 当哨兵再按 `goodMs + 60` 推。`UserSettings` 的默认值也取 200 保持新档一致。
- 启动多打一行 `[settings] windows perfect=.. bad=.. missAfter=.. holdTail=..
  linked=..`（`main.cpp` 判定设置生效块里），调试判定手感先看它。
- 设置卡片 380x700 → 380x780（判定页多了行）。

顺带补的组件能力（`game/Ui.*`）：
- `slider` / `checkBox` 加 `enabled=false`：画灰 + `ImGui::BeginDisabled()` 吞点击，
  **灰着时绝不回写值**（否则打开一次设置页就把值悄悄改掉）。判定页用它做
  「Bad 与 Miss 同步」时的 Miss 滑杆。
- `stepper` 加 pick-one 档：`presets.size() == deltas.size()` 时把 `*value` 当
  "选中第几项"（`-1` = 没选中，pill 显示 `--`），每个胶囊就是它自己那一项、按一下
  选它（**不是**按 delta 加减——第一版写成加减了，点一下直接掉到 -1）。胶囊宽度按
  `rowW` 和最长标签现算，否则三个中文标签会顶出卡片右边。
- 长条容错三档预览：宽容 180/140（原值）/ 较紧 120/80 / 严格 60/40；下面的滑杆
  拖到别的值就 `holdPreset = -1`（不再高亮预览）。

验证手法（这次踩到的坑）：`--screenshot` 出来的 PNG **是帧缓冲尺寸、和窗口不一定
一样**（本次 1280x720 的窗口出的是 900x520 的图，x/y 缩放系数还不相等），所以拿
PNG 像素坐标当客户区坐标去点会偏。要确认 UI 行为，靠日志比靠像素稳：
`[settings] windows ...` 一行就能验完读取路径；手写一个带
`badMs=250 missMs=310 linkBadMiss=false holdTail=90 holdStart=60` 的 profile 跑一次，
读回一模一样，就说明 JSON 键名和 clamp 都对了。

## 多人游玩：房间搬到选曲界面 + 修结算进不去（commit 0db2333）

用户四条需求 + 一个 bug，全部落地：

1. **只读列表**：成员的选曲列表整块只读（`listHovered` 直接对 `partyReadOnly` 取假，
   一次挡住滚轮/拖动/点选/甩动，连键盘上下都不动），列表上盖半透明灰罩 + 「只读·由房主选曲」
   胶囊（画在 child 的 draw list 上——父窗口的 dl 永远在 child 之下）；搜索框/排序/分组/刷新
   用 `BeginDisabled` 包住再用 banner 盖掉（banner 画在父 dl 的后面 = 在上面），随机按钮灰掉。
2. **房主焦点即广播**：`publishHostSong()` 在选曲分支每帧跑（光标换曲 → lockSong → epoch++），
   成员手机面板显示房主的曲目（drawSongSelect 里把 groupIndex/selected 强推到 lockedEntry，
   列表还会自己滑过去），难度就在手机面板那排圈里点。
3. **确定即开**：房主的确定=锁定+ready，成员的确定=ready，最后一个按下→ beginCharging
   **只加 lead-in**（旧代码是 4s 加载宽限 + lead-in = 10s，就是用户嫌的"等待10s"）。
   白色确定闪光改到 charge 加载那一刻点亮（这里没有异步加载，所以别设 confirmStartPending）。
   房主连按两次 = 强制开始；成员可「旁观」（座位退回 Lobby，不卡房主）。
4. **结算进不去**：根因是多人路径从没调 `announceTrack()`，`trackDurationSec` 恒 0 →
   `resultDue` 永远假。现在加载后两边都调，房主还用 `publishTrackEnd` 把曲长写进共享页
   （共享块加 `trackEndMs`，映射名升 v2，老窗口读不到新布局就不会错位）；
   成员没有 BGM，自己算曲长会拿谱面末音符当曲终，比房主早好几秒。

其它：删掉 `AppState::Party` / `drawPartyScreen`（难度页被手机面板取代）与
`PartyDifficultyOption` / `buildPartyOptions`；座位进房即 `PartySeatChoosing`（新窗口也算在局里，
否则房主会在它看清之前就开局）；`allReady()` 的 `inRoom >= 2` 改成 `>= 1`；
新增 `--no-party`，`--party-auto` 也能当单机"按确定"用。

验证：`mp_verify.sh` 加第三轮（打到结算、两边同一 chart time、回选曲、房间重新武装），
三轮全 PASS；另抓了成员端只读界面 / 选完难度 / 房主端三张截图人工确认过
（**这台机器上我能直接看截图**，之前记忆里"看不了截图"的假设可以推翻）。

## 多人收尾三修（commit 见下）

1. **失焦一律忽略**：演奏态失焦那条老路径（lead-in 期间 `state = Select`）在两窗口互相点击时
   特别容易触发（"点了确定又退回选歌"）。现在只要**本机有房间**（启动时的 `roomOpen`）就跳过
   全部失焦处理，不只 `party.active()`。
2. **房主 放弃/重试 广播**：`releaseSong()` 回大厅 + epoch++，成员在演奏态每帧看一眼房间，
   发现 `phase == PartyLobby` 且 epoch 变了就 `leaveLiveForRoom()` 回选曲（新加的 lambda，
   统一收尾：停 BGM/结算曲/长条音、清触摸与按键、清座位分、回选曲）。
   多人里的「重试」= 重开本轮（大厅 → 重新广播同一首 → 全员再按确定），不原地重启。
3. **选歌试听与打歌 BGM 重叠**：房主 charge 后还停在选曲界面等 lead-in，而 BGM 已加载，
   试听每帧重启 → 叠音（所以看起来"概率"）。修法：`playPreviewHere` 加 `!mpStartPending`。
4. **charge 遮罩**：加载+等待都发生在选曲界面上，只留一行状态小字会被当成"又回到选歌"。
   现在 charge 期间盖一层 + 中央大数字倒计时（"即将开始 x.xs"）。
