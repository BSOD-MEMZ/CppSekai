### 渲染模式
- `UserSettings::renderScale`：0=窗口多大渲染多大 / 1=固定分辨率（FBO + 等比黑边）。
- 三件必须同时成立：`windowW/H`=渲染尺寸、指针事件在进 switch 前改写坐标、
  `ImGui_ImplSDL2_NewFrame()` 之后设 `io.DisplaySize`=渲染尺寸 + `DisplayFramebufferScale`=1。
  这样游戏/ImGui/触摸三套代码**零改动**。
- 分辨率预设降到 640x360 + 「自定义」宽高（提交才 resize，`IsItemDeactivatedAfterEdit`）。
- 无头检查：`--render-size <w>x<h>`（配 `--width/--height` 造出窗口≠渲染尺寸）。

### 验证手法（这轮摸出来的）
- **当前模型看不了图**，所以全靠：日志断言 + Pillow 像素探针 + `winsend` 点击。

  **同一个窗口像素**都要命中，日志出现 `[result] continue -> song select`。
- 注意 `--result-preview` 会在结算出现后 ~2.6s 自动截图退出，点击要在那之前**连点**。

## 2026-09-16 晚：手柄扩充 / 单实例 / 触摸 flick 调查

### 触摸 flick 调查（未改代码，结论已进 AGENTS.md）
- 主因：`movePointer()` 用**处理事件时**的 `SDL_GetTicks()` 当采样时钟，整帧事件同一毫秒 →
  `rawDt==0` 被 `dt>0.001` 整条丢掉。鼠标免疫（Windows 合并 WM_MOUSEMOVE），
  触摸不合并（WM_TOUCH 一次多触点）→ 所以"只有触摸屏难触发"。
- 次因：`flickDirFrom` 先判上（up >= side*0.5 即 UP），左右 flick 的斜划要在水平 ±37° 内；
  判错那次还会吃掉手势（位移清零 + 60ms 锁）。
- 阈值：1080p 下 500px/s 硬门槛，1440p 变 667px/s。数值模型在 main.cpp 注释里对应的常量上调过。

### 手柄（Xbox）
- A=确定/跳过开场/结算继续，START=暂停/设置，X/Y=暂停对话框重试/放弃，LB/RB=设置切页签，
  B/BACK=返回；**BACK 在演奏中改成暂停**（原来发 Escape = 放弃回选曲）。
- `ui::messageDialog` 新增 `forcedChoice`：手柄选择按"点了那个按钮"处理（含关闭动画）。
- 坑：同一帧 `pressed()` 只能调一次（第二次必为 false）；暂停对话框是自绘的，
  ImGui 焦点导航够不着，所以走 forcedChoice 而不是 NavEnable*。
- 新增 `--fake-pad <A,B,...>` 无头验证（30 帧压/30 帧松，多键错开半周期，6 周期后停）。

### 单实例 / 多开
- `UserSettings::instanceMode`（设置→系统 / `--instance single|multi`）。
  single：命名互斥体 + EnumWindows 找窗口并前置；multi：每实例占一个
  `Local\CppSekai.Profile.<id>`，自动换用户，全占满就建"用户N"。
- 实测三实例工作集 207/299/333 MB —— **线性增长，跨进程没法共享**（结论与可选方案写进
  AGENTS.md，本轮没实现共享）。
- `makeProfileId` 现在纯数字的名字也走哈希（"用户3" 曾得到 id "3"）。

### chartdl
- 分割手柄不再自绘（去掉 WM_PAINT 的斜纹），保留 8px 命中区 + 标准 IDC_SIZEWE/SIZENS 光标。

### 无头验证注意
- GUI 子系统进程的 stdout **不进管道**，一律看 `cppsekai.log`；且每个进程启动会**截断**它，
  多开时只剩最后一个writer 的内容。测多开要看单个进程的行为。
