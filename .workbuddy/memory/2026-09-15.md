## UI 组件动画（commit 2615a37）

- 用户要求「多加点动画，比如 combobox 的还有其它组件的动画」。做法是在 `game/Ui.cpp`
  顶部加两个小工具，取代每个组件各写一套：
  - `animValue(key, target, rate)`：按 ImGuiID 存在 `unordered_map` 里的一个值，
    每帧 `v += (target - v) * (1 - exp(-rate * dt))` —— 指数逼近，步长由 DeltaTime
    推出（帧率无关），且**永远不会过冲**（比弹簧稳，不需要额外阻尼参数）。
    差值 < 0.0015 直接吸附，免得为了 0.1% 的变化一直重绘。
  - `mixColor(a, b, t)`：用 ImGui 的 ColorConvert 做 RGBA 插值。
- 接进去的地方：tabBar（选中页签从下面滑上来 + 填色/文字色渐变 + 悬停提亮）、
  slider（`##thumb` 悬停/拖动时放大 16%，± 按钮悬停变亮、按下变暗都用插值）、
  capsuleButton（悬停放大 2%、按下缩 3%，颜色三层混）、checkBox（对勾从盒子中心
  `scale 0.5→1` 长出来 + 淡入，边框同时淡出）、stepper（胶囊悬停/按压插值）。
- 顺序坑：slider 的把手原来画在 `InvisibleButton` **之前**，拿不到 hover 状态 —— 把
  绘制挪到 ± 按钮之后，用 `ImGui::GetID("##thumb")`（不是 `GetItemID()`，那时它已经是
  最后一个按钮的 id）当 key。
- 新增 `ui::combo()`：包一层 `BeginCombo`。
  - 淡入：ImGui 每帧重建 popup，所以"渐变"全靠 `PushStyleVar(ImGuiStyleVar_Alpha, …)`
    包住 BeginCombo，配合 popup 打开状态（`IsPopupOpen("##combo", …)`）驱动的 0→1。
  - 旋转箭头：`ImGuiComboFlags_NoArrowButton` 关掉内置箭头（它画在控件内部，动不了），
    自己在 `GetItemRectMin/Max()` 右端画一个三角形，按 `t * π` 绕中心旋转。
  - 最后一个参数 `scaleHint`：选曲界面用的是自己的 `k = h/1080`，和 `ui::scale()`
    （h/860）不是一回事，不传的话箭头大小会不匹配。
- 验证：`--screenshot`（选曲）+ `--settings --settings-tab 1`（设置）两张静态图都正常
  （像素统计：几万种颜色、亮度分布正常），动画本身没做逐帧回归。

## 下载器歌曲表去重（同一个 commit）

- 用户报「搜索チーム出现两个 id 一模一样的チームメイト」。查下来**本地数据里没有重复**：
  `musics.json` 715 条 id 唯一、仓库根和 build/ 两份 md5 相同、`chartdl --list` 全表
  只有一条 `0374 チームメイト`。`--list <日文>` 也没法用来复现 —— exe 走窄 argv（ACP），
  日文过滤器传进去是乱码（**踩坑：验证日文搜索别用 `--list`，只能用 GUI**）。
- 结论：重复只可能来自他用过的那份数据/那个 exe。按需求做了防御性去重，并且**让它在日志里
  可见**，而不是悄悄吞掉：`loadData()` 用 `std::set<int>` 丢掉后来重复的 id，
  `rebuildList()` 再用一个 set 兜一层（哪怕 gSongs 被别处污染），丢弃条数打印成
  `[data] dropped N duplicate song id(s)`。理由写在注释里：输出文件名 `0374_normal.sus`
  完全是 id 拼的，同 id 两条记录既重复列行、又会让两个下载任务抢同一个输出路径。

## 下载器绑 Common Controls v6（同一个 commit）

- 用户说的「Windows 那个什么什么组件库 6.0 的系统存根」= `Microsoft.Windows.Common-Controls`
  6.0 的 **SxS 程序集依赖**（通过应用清单声明）。
- 做法：新增 `app.manifest`（`<dependency>` 指 v6 + `asInvoker`），`app.rc` 加一行
  `1 24 "app.manifest"`（RT_MANIFEST = 24，CREATEPROCESS_MANIFEST_RESOURCE_ID = 1）。
  `zig rc` 直接支持 `ID TYPE "外部文件"` 这种写法，不用内联。游戏 exe 和下载器共用
  `build/app.res`，所以两个都带上了（游戏不用原生控件，无副作用）。
- **没有加 DPI 声明**：`dpiAware` 会改变窗口的实际尺寸（高缩放屏上界面变小），用户没要求，
  先不动。
- 验证方法（可复用）：起一个实例，PowerShell 看进程模块
  `Get-Process chartdl | % { $_.Modules | ? ModuleName -eq 'comctl32.dll' } | % FileName`，
  结果落在 `C:\Windows\WinSxS\amd64_microsoft.windows.common-controls_6595b64144ccf1df_6.0.19041.6456_none_...\COMCTL32.dll`
  就是 v6；绑到 `C:\Windows\System32\comctl32.dll` 就是没生效。
  **注意 `FileVersionInfo.FileVersion` 显示的是 5.82**（那是 MUI 资源的旧号），别拿它当判据。

## 第三轮：页签 / 换歌 / 列表重建过渡（commit fdff465）

- **设置卡片换页签**：新页内容从下方 14px 滑入（0.18s，ease-out）。改动只有一句话
  ——把 child 内初始 `SetCursorScreenPos` 的 y 加上 `tabSlide`。**这里刻意用位移而不是
  淡入**：页签内容里既有 ImGui 原生控件又有 `ui::` 手绘部件，前者认
  `ImGuiStyleVar_Alpha`、后者不认，混着淡入会一半淡一半不淡；位移对所有部件一致。
- **手机面板换歌**：内容块（封套/元数据/难度圆/徽章）上浮 16px + 淡入，手机框不动。
  复用了文件末尾那个"把所有 phone 顶点做 tilt"的 pass：在内容开始处记
  `phoneContentVtxFirst`，pass 里用 `i >= phoneContentVtxFirst` 区分内容与边框，内容额外
  加 y 偏移、alpha 与入场动画取 min。
  **这个套路值得记**（顶点范围 + 事后一次 pass）：想让某块绘制整体动起来时，先记
  `dl->VtxBuffer.Size` 当分界，事后再统一改 pos / col —— 不用碰那块绘制的任何一行代码。
- **列表重建**：`listSignature` 变化时 `listIn = 0`（新列表上浮 12px + 淡入），与
  section index 的淡出共用同一个顶点 pass（原来那个 pass 只在 `indexAnim > 0` 时跑）。
- **验证踩坑（重要）**：用 `--screenshot` 默认的 1.2s 做"静止态无回归"对比**会误判** ——
  选曲界面 mean 从 101.2 掉到 93.8，看着像改坏了，其实只是截图模式帧数少、动画没跑完
  （`frameDt = clamp(io.DeltaTime, 0.0005, 0.05)`，截图模式一帧最多算 0.05s）。
  把 `--screenshot-time` 给到 2.5 / 4 之后与改动前逐项一致（101.2/107.2/127.9）。
  **以后凡是对比静止态，时间给足再比。**
