## 设置页按手柄在线状态隐藏手柄设置（提交 639f8cc）

需求：设置页先检测有没有插手柄，没有就把手柄相关的行静默隐藏。

- 手柄专属的行**只有 演奏 页那一段**（全仓 grep `手柄` 只有一处文案）：
  `手柄震动` 滑杆 + `震动` 三个勾选框 = `padRumble` / `rumbleFlick` /
  `rumbleCritical` / `rumbleMiss`。判定页那处只剩注释（震动已经搬走过）。
- **`按键映射` 是键盘的（12 个 lane 键），不是手柄，别一起隐藏。**
- 判定依据用 `pad != nullptr`（`openPad()` 内部走 `SDL_IsGameController`，
  只认 SDL 认得的手柄，不是裸 joystick），没有按 `SDL_GameControllerHasRumble`
  再收窄——没有马达的手柄本来就极少数，而且 `rumble` lambda 自己会挡。

### 坑：lambda 看不到定义点之后声明的局部变量

`drawSettingsCard` 是 `auto drawSettingsCard = [&]() {`，定义在 **main.cpp:3476**；
而 `SDL_GameController* pad` 到 **5193** 才声明。`[&]` 也拿不到——lambda 体的
名字查找在 lambda 表达式出现的位置就做完了，后面声明的局部变量不在作用域里。
（同理 `runFrame` 在 5401，它**能**看到 `pad`。）

所以加了一个提前声明的 `bool padConnected = false;`（放在 drawSettingsCard 之前），
由 `runFrame()` 每帧刷新。

**刷新点选在帧内的手柄轮询处**（`if (pad != nullptr || !fakePad.empty())` 之前），
不是 `openPad()` / CONTROLLERDEVICEREMOVED：热插拔只负责 `SDL_GameControllerClose`
+ 置空指针，拔出后标志位会一直是 `true`，设置页就继续显示不存在的手柄的行。
每帧过一遍不会残留。

主循环结构（改 main.cpp 的 UI 时要记住）：`runFrame()` 是个 lambda，
里面是 `for (bool once = true; once; once = false)`，`continue`/`break` 只作用于
这个单次循环（本来是用来模拟"离开主循环"的），外层 `while (running) { runFrame(); }`。

### 验证手法（新学到）

`--fake-pad <不存在的键名>`（比如 `NONE`）可以伪造"插入了一个不会按的手柄"：
`fakePad` 非空 → `padConnected` 为真、设置页照常显示，但 `padDown()` 拿它跟
SDL 的按键名比对永远不匹配 → 一个键都不会按下去，不会乱点界面。
用来无头验证"有手柄"那条分支正好。

## 猴子测试（240 用例，报告在 `.workbuddy/monkey-report-2026-10-04.md`）

工具 `.workbuddy/tools/monkey_test.py`。**数据必须隔离**：`userDataPath()` 在
`<exe>/../charts` 存在时把数据写到**上一层**（build/ 布局就是仓库根），
所以直接跑 build/ 里的 exe 会动着 `D:\Dev\CppSekai\profiles\`。
沙箱复制一份 exe + assets + 少量谱面到 `%TEMP%`，数据文件全在沙箱内生成。

三条输入通道：参数（104）、文件（23）、可编辑数据文件（31）、
`--fake-pad` 随机按键（72，**它推真 SDL 事件所以能驱动 UI**）、关窗退出（4）。

### 找到的（详见报告）
- **P0 `--ui-scale nan` 直接访问违例崩溃**。根因是 **`std::clamp` / `min` / `max`
  都不消 NaN**（`v < lo ? lo : (hi < v ? hi : v)`，NaN 比较全 false → 原样返回），
  而 `atof("nan")` 给得出 NaN。NaN 穿到 `SongSelect.cpp:2590` 的 `k`（px-per-unit）
  再进到整屏布局。**以后任何 `clamp(用户输入)` 都不能当成消毒**。
- **P0 `profiles/index.json` 的 `id` 不校验就当路径拼**（`profileDataPath`），
  实测 `"../../escaped"` 能写出 data 目录外面。
- P1 `--speed > 12` → `pow(负数, 1.31)` = NaN（上游 `mmw_preview.cpp:730`）
  → 音符时长 NaN → **演奏区一个音符都没有，但判定照跑**（截图确认）。
- P1 `loadUserData` 用 `s.value()`，**一个字段类型错就抛**，外层 `catch (...)` 全吞、
  零日志 → 该字段**之后**的所有设置静默回默认，下次保存永久化（截图确认）。
- P2 取值开关缺值时不报错、直接吞掉下一个开关（`--sus --screenshot` → headless 挂死）；
  `--settings-tab ≥ 6` 空白卡片（分支链没有兜底 else）；谱面不校验格式且
  "空文件 exit 1 / 二进制 exit 0 空舞台" 不统一。

### 验过没问题的
参数全有 `i + 1 < utf8Argc` 保护；72 个手柄猴子用例零异常（无断言、无卡死）；
所有脏数据文件（userdata / index / profile / 四个表 / chartdl）都能扛；
导入前有 `isUserDataFile()` 筛查。

### 两个方法论教训
1. **别把用例名写进日志签名**：签名里有 `nan`，而日志会打 `screenshot saved: ...cli-speed-nan.png`，
   于是十条"可疑"全是假阳性。日志扫描要跳过自己产出的路径行。
2. **报 bug 前先读实现**：我一度认定"导入垃圾文件会毁 profile"，读了才发现有
   `isUserDataFile()` 筛查；也一度以为坏谱面是"完全静默退出"，分开抓 stdout/stderr
   才发现错误其实进了 `cppsekai.log`（GUI 子系统进程的 stderr 重定向抓不到）。
   差一点报两条假的。

## 修「坏谱面提示」（提交 01f8e2f）

判据是 **hit event 数 == 0**（`--dump-events 1` 直接看：正常谱面 1040，坏文件 0）。
`loadSusTextPrecise` 对"能解析但没音符"的文件返回 **true**，所以之前一路走到底、
放个空舞台。三种"文件不可用"里，读不出来和解析失败本来就有报错，只有这条漏了。

改动：
- `startSession` 里 `count == 0` → 返回失败，`error = "chart has no notes (corrupt, or not a SUS file): <path>"`。
- 提示条画在帧循环 overlay 块**之后**（那块早已闭合，`w`/`h`/`fg` 不在作用域里，
  要自己重新声明——第一次编译就是这么挂的）。
- 三个玩家入口（选曲确认 / 暂停弹窗重试 / 中途重开）都走 `reportLoadFailure()`。
  **必须显式传 entry**：`startSession` 是检查通过之后才 `session.entry = entry`，
  失败时那个字段还是上一首。
- 观感用 sekai-stories 的 `.middle-information`（#44466 底 + 白字），和之前的对齐一致。
