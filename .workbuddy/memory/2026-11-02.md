## 选曲列表「选中项颤抖」（commit 2aac1cb）

**根因不是动画参数，是副本互相拉扯**：`slotHeights` 用 `wrapSlot(slot)` 做索引，
而列表是**循环**的——曲库比一屏槽位少时同一首歌会同时出现在多个槽位上，那些副本
共用一个高度状态，每帧各自朝 `cardH(128)` / `compactH(84)` 趋近。

探针实测（临时 `CPSEKAI_SEL_TRACE`，已删）：2 首曲子时 `rowH` 收敛到 **98.3**（不是 128），
而且每帧在 97.88~98.33 之间来回 → 卡片边缘和文字（ImFloor 后）逐帧跳 1px = 看到的"颤抖"。
算出平衡点 `(128 + 84n)/(n+1)`，n=2 即 98.67，与实测吻合，`rowCount=3` 时同屏 9 个槽位。
40 首的大曲库没有同屏副本，所以一直是 128.000——**只有小曲库能复现**。

修法：`unordered_map<int,float>`，键是原始 `slot`；`listSignature` 变化 `clear()`；
行循环后把 `[firstSlot-4, lastSlot+4]` 之外 `erase`（槽位号随循环无限增长，不清是慢泄漏）。
验收：小/大曲库都收敛 128.000 且不再变；截图量卡片 128px。

## 触摸轨迹日志（同上 commit）

设置 > 判定 > Flick 组新增「触摸轨迹日志」复选框（默认关，存档案 `debugLog`）。
**这个开关一直存在、但从来没有 UI**——`f616630` 只加了 `--flick-log` 和字段，
所以文档里写的「设置 > 判定 > Flick 调试日志」在界面上根本找不到。

新增 `[traj]` 行：手势里每一个 `SDL_FINGER*`，**在 `beginPointer` 的区域过滤之前**记录
（落点在地平线以下的手指以前一行都不留，于是"这块屏不发 motion"和"滑得太短"分不开）。
up 行汇总 `samples/held/dx/dy/peak/maxGap`；move 行带 gap；down/up 立刻 flush，move 每 32 行 flush。
轨迹状态 `trajTouches` + `trajRaw` 放在事件循环之前，**不在 `case SDL_FINGERDOWN` 里调**
（那里被 state / paused / autoplay 分支切碎，会漏事件）。

验证手法（可复用）：沙箱里 **EnumWindows 看不到游戏窗口**（不同窗口站/桌面），
所以 PostMessage 注入鼠标那条路走不通；改用**临时** `SDL_PushEvent` 伪造 FINGERDOWN/MOTION/UP，
验完删掉。注意 SDL 会给 push 进去的 finger 事件重写 timestamp（gap/held 量到 0），
真实触摸才有意义。
