## 开发环境重建（新机器 / 目录被清空后）

初始状态：仓库是干净的 fresh clone（所有文件 17:26 同一时间戳），`toolchain/` 里只有
一个 1.3MB 的 `zig.zip` 残片，没有 `build/`，`assets/` 反而是齐的（在库里）。

### setup.sh 在这台机器上跑不通，两个原因
1. **`curl --max-time 600` 是硬伤**：zig 0.14.1 的 zip 有 **82,229,343 字节**（不是记忆里
   以为的 45MB），单连接约 65 KB/s → 600s 只下到 39MB 就被掐断。
2. **退出码被管道吞掉**：`bash setup.sh 2>&1 | tail -40` 的退出码是 `tail` 的 0，
   所以「curl 超时 abort」看起来像「成功但没输出」。判断成功与否**只能看文件系统**
   （`toolchain/zig014/.../zig.exe` 是否存在），别信 `set -e` + 管道。

### 正确姿势
```bash
node .workbuddy/tools/seg_download.js \
  "https://ziglang.org/download/0.14.1/zig-x86_64-windows-0.14.1.zip" \
  toolchain/zig.zip 82229343 8 8        # 4m40s，0.3MB/s 均速
python -c "import zipfile; zipfile.ZipFile('toolchain/zig.zip').extractall('toolchain/zig014')"

# GitHub 直连不通（HEAD 完全无响应），SDL2 走 gh-proxy：
node .workbuddy/tools/seg_download.js \
  "https://gh-proxy.com/https://github.com/libsdl-org/SDL/releases/download/release-2.32.10/SDL2-devel-2.32.10-mingw.tar.gz" \
  toolchain/sdl2.tar.gz 13892870 6 4    # 1m02s
tar -xzf toolchain/sdl2.tar.gz -C toolchain/
```
`setup.sh` 里的 assets / music-levels 两段本来就已经满足（assets 在库里、
`music-levels.json` 也在），**没重跑**，避免覆盖。
