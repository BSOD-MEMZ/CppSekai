新增两个脚本（都在 `.workbuddy/tools/`，已入库）：

- `il2cpp_disasm.py <so> --range 0xA 0xB` / `--va`：解 PT_LOAD 拿文件偏移，
  capstone 反汇编 arm64，顺手把 `adrp+ldr` 的目标地址和分支目标打在行尾。
  踩过的坑：ELF64 的 `e_phentsize` 在偏移 **54**（不是 52），写错会得到垃圾段表。
- `il2cpp_where.py <dump.cs> 0xADDR`：VA 反查所属方法。**dump.cs 的 RVA 注释
  在方法声明上一行**，配对要「先记 RVA、后遇声明」，反过来会整体错一位。

`dump.cs` 只有签名，**`MusicScoreInfo` 是 struct（0x1C 字节）且内联在
NoteBase 0x70**，所以 `[x19+0x78]` 是 `MusicScoreInfo.time`；`0xB0` 是
`parentNote`。实例方法参数 float 走 `s0..s7`、整数走 `x1..x7`，两套独立，
按「总第 N 个参数」数会错。

### 结论（全文写进 `JUDGE-WINDOWS.md` §4）

- flick 门槛 = **单帧瞬时位移**（`delta / (deltaTime/(1/60))`）> `flickDistance`
  px；**不是**累计行程。`flickDistance` 来自 `LiveBundleBuildData.FlickDistance`
  （SerializeField 0x40，运行时 `GenerateNote` 原值直传），**该资源不在解包里，
  具体像素值未知**。`LiveUtility.ScreenDpiToInch(x) = x*dpi/2.54` 只给谱面编辑器用。
- 方向 = `dot(normalize(v), dir) >= 0` 一个符号点积，**没有角度容差**；
  `NoteDirection.Default` 反着甩也算对。
- **方向错的后果是「上限 Great」**：落在 Perfect 窗口内给
  `(Great, NoteResultDescription.FlickMiss)`，落在外面走正常 Great/Good/Bad 阶梯。
  不是 MISS，也不只是"不判"。
- 有 **JustPerfect 档**：`|offset| <= 1/120 s (8.33 ms)`，**且只有方向对才给**
  （`GetJudgeResultInternal` 里 `tbz isDirection` 直接跳过这段）。
- 时序：独立 flick 在 `Playing` 只接 `phase==Began`，那一帧只 `AddInputResult`
  记 `(touchId, 过了门槛, 方向对)` 后 return false，**下一帧 `Moved` 才定案**。
  长条尾 flick 不走 phase，但要求 `noteTime - touchTime <= -1/120`（**必须晚 8.33ms 以上**）
  且方向对，否则干脆不判（保持 pending）。
- `inputResults` 是**定长 8** 的数组（最多 8 指）。
- **自动 MISS 用全局 `max(BadAfter)`**（141.7 ms，flick 那一行贡献的），
  不是逐类型；顺序是 `UpdateJudgeTimeBeforeAndAfter` 里取 max 塞进
  `noteTypeJudgeData.JudgeTimeAfter`。
- 顺带**验证了 §1 表的 Before/After 读法是对的**（窗口 = `[-After, +Before]`，
  offset = `noteTime - touchTime`，正 = 早）。
- `LiveConfig` 常量：`JustPerfectJudgeTime=1/60`、`Half=1/120`、`JudgeTime=0.125`、
  `Life=1000`、`MaxSkillCount=6`。

## 下午：舞台区判定对齐（flick 方向 + 触摸平面）

用户反馈：音符在屏幕上半部分反而更容易判定，flick 在触摸屏上极难触发。

反汇编确认（`CreateLiveTouch` 0x545763C / `IsJudgment` 0x506F818 / `LiveTouch` 字段）：
- 原作用 `Camera.ScreenToWorldPoint` 把手指投到**固定世界平面**，`lane` 只跟屏幕 x 有关；
  音符横向区间用 vtable 0x458/0x478 两个边界比，**没有额外 margin**。
- 我们原来 `lanePos = clipToWorldX/worldY`（撤销伪透视），同一屏幕 x 在屏幕上部会被放大
  ≈2.6 倍；追着 sprite 点永远正中 → 「上半部分更容易」。已改成 `lanePos = clipToWorldX(clipX)`
  （判定线 y=1 平面）。
- flick 方向：原作 `dot(v, noteDir) >= 0 || Default` —— 纯竖直上滑对左右 flick 都算对；
  Direction==Default 恒真。我们原来要求 `flickDir == noteDir`，上滑打不了左右、上 flick 只认纯上滑
  （而分类器 0.85 偏置经常把上滑判成侧滑）→ flick 极难触发的主因。
- 方向错不是 MISS，是**上限 Great**（Perfect 窗口内 (Great, FlickMiss)）；已实现降级，
  有方向对的候选时优先。
- 长条尾 flick 必须晚 ≥1/120（8.33ms）；已加。

改动：`game/Judgement.{hpp,cpp}` 新增 `flickVector()`（向量方向判定 + 双候选槽 + Great 封顶）、
`main.cpp` flickJudge 改传 vel/peak 向量、flick 判当前 lane（lastLanePos 提前更新）、
start/move 的 lane 映射改固定平面。新增回归单测 `.workbuddy/tools/judge_flick_test.cpp`
（8 项全过）。`--test-hits` 跑 0075_master 20s：perfect=175 good=3 miss=0。
