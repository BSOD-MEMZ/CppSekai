## 第三批：hold 半拍 combo / autoplay 音效 / 失焦暂停修正（a7287ab）

1. **hold combo 按半拍计**：pjsk 机制（巴哈姆特公式帖证实："八分拍中继点为 SLIDE 进行
   过程中所有非钻石之 COMBO 加分，0.1 倍权重"）——hold 按多久 combo 涨多少，不是只有
   首尾。unipjsk SUS 几乎没有可见 mid，所以原来一个 hold 只 +2 combo。修法：核心
   calculateHitEvents 里镜像上游 HoldHalfBeat pass（起点向上取整到下一个八分位、终点
   向上取整、不含端点），合成 kind-4 tick 进 HitEvent 流，同时去重同时间同轨道的
   kind-4。合成 tick 复用 tick 门控逻辑（按住才计分）。判定 0002 全连 121→136。
2. **autoplay 音效**：判定流的 lastJudge 变化处补 playHitSe（kind 0-3，tick 静默交给
   hold loop SE）；特效仍由核心时间线负责，不会双份。
3. **失焦暂停修正**：之前只设了 paused/pauseDialogOpen，没调 audio.pause()——弹窗开着
   但音乐照跑（=用户说的"游戏还在运行"）。现在同 ESC 路径调 audio.pause()。
4. **默认帧率 60**：main.cpp 与 UserSettings 默认值 0→60（旧存档保留用户自己的值）。
   坑：`--auto` 无头验证运行退出时会把 autoplay=true 持久化进 userdata.json，污染后续

## 第二批：AUTOPLAY / SMTC / 失焦暂停 / 帧率（0c1359f + dff1c55）

1. **AUTOPLAY 谱面预览**：设置面板复选框（持久化，`--auto` 仍可覆盖）。判定引擎
   `setAutoPlay(true)` 后 update() 把每个可击中音符按自身时间 PERFECT 结算、hold 永不断、
   尾判全 Perfect；HUD 显示官方 AUTO 精灵 `judge_6`（动画时序同普通判定字）；特效走核心

   成绩。上游预览其实显示的是 PERFECT 字样，AUTO 是官方样式——用户点名要 AUTO。
2. **SMTC 修复（真凶）**：`ITimelineVtbl` 的 put_StartTime/EndTime/Position 参数是
   `Windows.Foundation.TimeSpan`（8 字节 struct，x64 ABI 按值传）——原代码传的是
   createTimeSpan 的 boxed IPropertyValue **指针**，时间轴全是垃圾刻度，系统面板根本
   无法显示进度。现在直接传 INT64 tick，删掉 PropertyValue 打包路径；加了一次性
   HRESULT 诊断日志（[media] put_PlaybackStatus / UpdateTimelineProperties），实测
   双双 S_OK。 WinMD 槽位脚本对 get/put 的签名假定（void*/void**）对 TimeSpan 接口
   不成立——以后核对槽位时参数类型也要对着 winrt 元数据看。
3. **窗口失焦自动暂停**：SDL_WINDOWEVENT_FOCUS_LOST 且在 Play 态时自动开暂停弹窗
   （screenshot 模式豁免）。
4. **帧率 >60 乱跳**：不是显卡问题——垂直同步下呈现按刷新率量化，60Hz 屏上 >60 的
   上限物理不可能，软限帧在 vblank 附近抖动就表现为乱跳。现在 `fps > 刷新率` 自动关
   垂直同步、纯软限帧（会有撕裂），面板显示检测到的刷新率。
5. **视奸（モニタリング）谱面**：musicId **628**（musics master 查的）。SUS 源

## miss 音符滑出屏幕 + hold tick 白送 Perfect 修复（f1ae2f5）

两个用户报告的问题一起修了：

1. **hold tick 未击中也全 PERFECT**：`JudgementEngine::update()` 里 kind 4 tick 原来无条件
   auto-hit。现在 load() 预计算每个 tick 的 `holdStartIndex`/`holdMarkerIndex`，tick 只在
   「起点已击中且 hold 未断」时 auto-hit；起点 miss / hold 断了就静默吞掉（state=2，
   不重复 miss）。**匹配必须按时间窗，不能按中心**——hold 走位时 tick 中心≠起点中心
   （第一版按中心匹配漏了 7 个白送 PERFECT 就是这个原因）。
2. **miss 音符停在判定线**：核心 `approach()` 本来就能外推到线外，音符是被
   `visualTime.max == targetTime` 的窗口判断裁掉的。把 drawingNotes 窗口延长一个
   visibleDuration，miss 的音符自然滑出屏幕。击中的音符由宿主经新 C API
   `markNoteHit(HitEvent索引)` 隐藏（核心加了 hitEventNoteIds→noteID 映射，与事件流
   同序排序）。miss 的 hold（起点没打到）经 `setMissedHolds()`（与 dimmedHolds 同款
   (center,startTime) 键）让主体继续下落而不是停在线上，tick 也延长窗口。
   autoplay 不发布任何东西，核心按 `effectsAutoplay && t > hitTime` 保持上游"到线即消失"。

接线：main.cpp 里 `s_hitPublishCursor` 增量发布命中索引（startSession 重置），
`judgement.missedHoldKeys()` 每帧全量发布（仅 !autoPlay）。

验证（全部无头）：挂机 miss_fall3 = perfect 0 / score 0 / miss 105（旧版 7 个白送
PERFECT）；`--test-hits` 全连 121；`--test-restart` 正常。

其它：把用户落下的 TapEffect WIP（TapEffect.*、build.sh、main.cpp 接线）单独提交为

## 追加（dc3ac2e）：音符全部散架 = approach() 锚点被污染
第一版把 `DrawingNote.visualTime.max` 延长来实现 miss 滑出——但 `visualTime.max`
同时是 `approach(min,max,t)` 的**判定线位置锚点**，延长它等于把整条下落曲线拉长，
所有音符晚一个 duration 才到线，全场错位（用户："音符全部散架了"）。
教训：**核心里 Range 字段既是裁剪窗口也是位置锚点，延长窗口必须另开字段**
（现在叫 `fallTime`），位置公式永远用原窗口；过线后的下坠靠 approach() 自身外推。
tick 和 hold 主体的窗口延长没踩这个雷，因为它们的位置锚点是音符自身时间。

## 异形 PNG 开屏（2026-09-12 修）
- 用户要的是异形图 alpha 直接透到桌面，不是铺满/黑底。SDL2 **没有** SDL_WINDOW_TRANSPARENT
  （那是 SDL3），SDL2 手动做法：建 GL context 前 `SDL_GL_SetAttribute(SDL_GL_ALPHA_SIZE, 8)`，
  context 建好后动态加载 dwmapi 的 `DwmExtendFrameIntoClientArea(hwnd, margins={-1,-1,-1,-1})`，
  之后 GL 清屏 alpha=0 → DWM 透出桌面，alpha=1 → 正常不透明，所以该状态可全程保持
  （游戏主循环 Renderer.cpp:749 的 clear alpha=1，不受影响）。
- 图片按**原始尺寸**居中画，图片比窗口大才会被窗口边界裁掉。
