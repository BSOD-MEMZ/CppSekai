## 下载器：搜索框输入假名必崩（已修）

- 用户报「谱面下载器里用微软输入法打一个假名，程序卡死并自动退出」。
- WER 记录：`chartdl.exe` / 故障模块 `ucrtbase.dll` / 异常码 `0xc0000409` /
  **异常数据 `7` = FAST_FAIL_FATAL_APP_EXIT**（= `abort()`）/ `EventType=BEX64`。
  也就是说**抛了个没人接的异常**，不是内存踩坏了。
- 复现（不用真的 IME）：给搜索框发 `WM_CHAR U+3042` 即崩；`ã`(U+00E3)、`ÿ`(U+00FF) 不崩；
  同样的假名发给**另一个 EDIT**（输出目录框，EN_CHANGE 不处理）也不崩 → 崩在自己这段。
  （顺带：`WM_SETTEXT` 改搜索框文本**不会**触发 EN_CHANGE，所以之前用 settext 试是假阴性。）
- 根因就在一句里：`windowText()` 的 `std::string(wideToPath(buffer).string())` —— 把 UTF-8 字节
  塞进 `fs::path` 再 `.string()` 取回来，而 Windows 上 path 内部是宽字符、**窄的一端是本地 ACP**
  （这台机器 ACP=936 Shift-JIS）。假名 UTF-8 = `E3 81 82`：`E3 81` 是合法 SJIS 双字节字，
  `82` 是孤立引导字节 → libc++ 抛 `filesystem_error: __char_to_wide: Illegal byte sequence`。
  单独写了个 10 行的 pathconv.cpp 验证过，就崩在这一句。
  `ã`/`ÿ` 的 UTF-8 只有两字节且都是合法 SJIS 单字节假名，所以不崩 —— 这就是"只有假名会崩"的原因。
- 修法：新增 `toUtf8()` / `pathText()`（= `toUtf8(path.native())`）/ `windowTextW()`；
  `windowText()` 改成 `toUtf8(windowTextW(ctrl))`（纯 `MultiByteToWideChar`）；
  **`gOutDir` 从 `std::string` 改成 `std::wstring`**（顺带修了非 ASCII 输出目录被 ACP 转坏的问题）；
  `path.string()` 全部换成 `pathText()`；`.part` 路径改用 `path.native() + L".part"`。
- 验证：修后连发 `U+3042`/`U+3046` 都活着；截图里搜「うみ」把 715 首筛成 3 首。
- **游戏本体有同类隐患但触发条件不同**：`SongSelect.cpp` 到处是 `path.string()` / `fs::path(窄UTF-8)`，
  一旦谱面文件名含 ACP 表示不了的字符（中文/emoji 的自制谱），扫描时就会抛同一个异常 → 启动即崩。
  今天没动（要统一改 susPath 的编码约定），先记在 AGENTS.md 的坑那一节。

## 贴图降分辨率省内存

- 起因：用户问 200 多兆内存是否正常，确认后让压缩部分贴图。
- 先量清楚：loadHud 那套实际 26.3MB（其中 effect.png 4MB、start_grad 3.8MB、life 数字
  约 13.6MB）；非 HUD 的 background_overlay 16MB、**stage.png 22.2MB**、notes 9.2MB、effect 4MB。
  `stage.png` 是 2048x2840 但只有上面 1176 行被采样（sprite 矩形写死的）→ 纯浪费 13MB。
- 做法：`loadTextureFromFile(path, err, maxDim, cropHeight)` 解码后**裁行**（cropHeight）+
  按**整二次幂**缩（maxDim）；数值集中在 Renderer.cpp 顶部一组 `k*MaxDim` 常量；
  **不动素材文件**。`CPSEKAI_TEX_RAW=1` 关掉全部压缩做 A/B；`[tex] N MB uploaded` 日志给出精确值。
- 踩坑：第一版限幅循环写错（`while (max/limit >= 2) limit *= 2`），2048 传 1024 会被跳成
  2048 等于没缩；改成"因子逐个翻倍，且必须能整除"，顺便把裁剪和缩放拆成两步。
- 结果（同一二进制 A/B）：上传量 53.2MB → **25.2MB**；进程内存 377.5MB → **312.4MB（-65MB）**。
- 验证：raw/opt 同帧对比里 HUD / LIFE / COMBO 区域**逐像素一致（差 0~1）**；音符区差异
  （mean 54）与 raw-vs-raw 的噪声（mean 41）同量级 → 属于两次运行的帧抖动，不是改动的锅。
  教训写进 AGENTS.md：别拿单帧 diff 当回归标准。
