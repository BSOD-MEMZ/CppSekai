# 2026-09-14

## 新机器首次构建 + 修舞台背景纵向拉伸

- 换机器后 `bash build.sh` 全量重编：5m53s 通过（只有 DirectXMath 的
  `-Wdefaulted-function-deleted` 警告，无关）。二次增量 1m39s。
- **bug：打歌背景（歌曲专属 bggen 底板）纵向拉伸约 1.75 倍。**
  - 根因：世界坐标背景四边形在屏幕上是**正方形**（`worldBackgroundWidth` /
    `worldBackgroundHeight` 都由 `BACKGROUND_SIZE=2462.25` 除以屏幕方向尺寸得到，
    两边都是 2462.25 虚拟像素），默认板 `background_overlay.png` 本来就是 2048x2048；
    而 `buildStageBackground()` 直接把 2048x1168 的 bggen 板当纹理返回，
    `Renderer::setSongBackground()` 又按整张纹理做 UV → 纵向被拉 2048/1168≈1.75 倍。
  - 不是这台机器/这次 pull 引入的，从 178dd6d 移植舞台背景那次就少了一步；
    默认背景板不受影响（它本来就方）。
  - 修法：把上游 `renderToSquareBackground()`（TS 版在 `overlayBackgroundGen.ts`，
    官方 native 版在 `mmw-overlay-player.cpp` 的
    `composeOverlayBackgroundV3()` 末尾）移植成 `toSquareBackground()`：底板居中、
    四周 `wrap` 平铺成 `base.width x base.width`（2048x2048）。耗时几乎没变
    （819ms → 829ms）。
  - 复现/验证：`--sus charts/0075_master.sus --auto --dump-stage-bg <png>
    --screenshot <png> --screenshot-time 12`；底板从 2048x1168 变 2048x2048，
    截图里房间相框的横竖比正常了（之前相框又窄又长、整体被放大 1.75 倍）。
- **另一个还没动的差异（已写进 AGENTS.md）**：我们只合成 upstream 的 normal 四角，
  少 `MORPH_*_MIRROR` 那组倒影。当时注释说"mirror 是另一种布局用的"是**误判**：
  `center_mask` / `side_mask` 在 y≈680..1040 是有 alpha 的（191 / 128），
  说明这些倒影屏本来就会合上去（只是亮度低），少了它画面下半部分那几块屏是空的。
  代价是生成时间大概翻倍（每首歌多 4 次 morph），所以没擅自加，留给用户决定。
- 顺手：`AGENTS.md` 里上游路径写的 `D:\Dev\sekai-mmw-preview-web` 在本机不存在
  （实际 clone 在 `D:\Dev\mmw-preview-web`），改成仓库链接，不写本机路径了。
- 提交：b09b2a5（`game/StageBackground.{cpp,hpp}` / `CLI.md` / `AGENTS.md`）。

## 补上 mirror（倒影）那组合成

- 用户确认后把 `MORPH_LEFT_MIRROR` / `MORPH_RIGHT_MIRROR` / `MORPH_CENTER_MIRROR`
  三组四角也投进 sideJackets / center（顺序照上游：normal → mirror → cover 玻璃）。
- 顺手把四边形常量从 `constexpr Point name[4]` 改成 `constexpr std::array<Point,4>`，
  调用处就不用再写 `{{kSideLeft[0], kSideLeft[1], ...}}` 那种展开；新增一个
  `projectInto(layer, quad)` lambda 收口 6 次 morph。
- 耗时 829ms → 1127ms（不是翻倍：morph 的 overlay 只落在四边形包围盒里）。
- 验证：截图 diff 集中在 y≈660..1020（下半部分那几块倒影屏），max 143 / mean 1.16。
