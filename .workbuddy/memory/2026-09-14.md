## 新机器首次构建 + 修舞台背景纵向拉伸

- 换机器后 `bash build.sh` 全量重编：5m53s 通过（只有 DirectXMath 的
  `-Wdefaulted-function-deleted` 警告，无关）。二次增量 1m39s。
- **bug：打歌背景（歌曲专属 bggen 底板）纵向拉伸约 1.75 倍。**
  - 根因：世界坐标背景四边形在屏幕上是**正方形**（`worldBackgroundWidth` /
    `worldBackgroundHeight` 都由 `BACKGROUND_SIZE=2462.25` 除以屏幕方向尺寸得到，
    两边都是 2462.25 虚拟像素），默认板 `background_overlay.png` 本来就是 2048x2048；
    而 `buildStageBackground()` 直接把 2048x1168 的 bggen 板当纹理返回，
    `Renderer::setSongBackground()` 又按整张纹理做 UV → 纵向被拉 2048/1168≈1.75 倍。
  - 不是这台机器/这次 pull 引入的，从 178dd6d 移植舞台背景那次就少了一步；
    默认背景板不受影响（它本来就方）。
  - 修法：把上游 `renderToSquareBackground()`（TS 版在 `overlayBackgroundGen.ts`，
    官方 native 版在 `mmw-overlay-player.cpp` 的
    `composeOverlayBackgroundV3()` 末尾）移植成 `toSquareBackground()`：底板居中、
    四周 `wrap` 平铺成 `base.width x base.width`（2048x2048）。耗时几乎没变
    （819ms → 829ms）。
  - 复现/验证：`--sus charts/0075_master.sus --auto --dump-stage-bg <png>
    --screenshot <png> --screenshot-time 12`；底板从 2048x1168 变 2048x2048，
    截图里房间相框的横竖比正常了（之前相框又窄又长、整体被放大 1.75 倍）。
- **另一个还没动的差异（已写进 AGENTS.md）**：我们只合成 upstream 的 normal 四角，
  少 `MORPH_*_MIRROR` 那组倒影。当时注释说"mirror 是另一种布局用的"是**误判**：
  `center_mask` / `side_mask` 在 y≈680..1040 是有 alpha 的（191 / 128），
  说明这些倒影屏本来就会合上去（只是亮度低），少了它画面下半部分那几块屏是空的。
  代价是生成时间大概翻倍（每首歌多 4 次 morph），所以没擅自加，留给用户决定。
- 顺手：`AGENTS.md` 里上游路径写的 `D:\Dev\sekai-mmw-preview-web` 在本机不存在
  （实际 clone 在 `D:\Dev\mmw-preview-web`），改成仓库链接，不写本机路径了。
- 提交：b09b2a5（`game/StageBackground.{cpp,hpp}` / `CLI.md` / `AGENTS.md`）。

## 选曲手机面板：元数据左对齐 + 最好成绩评级徽章

- 用户给了原版手机面板截图，要求「元数据左对齐 + 右侧显示最好成绩等级，没打过显示 --」。
- 参考图（408x504 的裁剪，手机屏幕 x 12..384、宽 372）量出来的：
  - 元数据左缘 x≈38 → 距屏幕左 26px = 7% 屏宽；难度圆那排左缘 x≈35 → **两者本来就对齐**，
    所以左缘直接用难度圆那排的 `contentL = cx - panelW/2`（`panelW = 336k`，正好等于
    `rowW = 5*60k + 4*9k`）。
  - 徽章圆 d≈51、难度圆 d≈48 → 徽章 = 难度圆的 **1.06 倍**（我们用 `64*k`）。
  - 圆盘色 (140,137,169) 在底色 (85,83,120) 上 → **白 32% 透明**；字母色 (145,195,255)，
    和 `score/rank/chr/b.png` 的平均色 (119,172,254) 对上 → 字母就是游戏自带那张图。
  - 字母字形高 / 徽章直径 = 35/51 = **0.686**；`chr/*.png` 是 224x266、字形实心 185x242 在 +20+16，
    所以整张图要按 `diameter*0.686/(242/266)` 放大，再按字形中心 (112.5,137)/266 偏移。
  - 徽章竖直：原版中心在歌手行和 Vo. 行之间；按「元数据块整块居中」算出来的落点
    与原版只差 ~2px（用「徽章中心到封底的距离 / 封套高度」两个比例都比出 0.227 vs 0.234），
    所以就用整块居中。
- 实现：`addTextLeft()` / `ellipsize()`（按 UTF-8 整字删）/ `chartRatingFor()` /
  `drawBestScoreBadge()`；`ChartEntry` 新增 `bestScore`，`applyScores()` 灌入。
  等级取值顺序故意跟 main.cpp 的 `setChartRating()` 一致（官方表 → 谱面 level → 26），
  这样徽章和演奏中 HUD 的 SCORE RANK 永远一致。没打过画暗一档圆盘 + `--`。
- 验证：改了 5 次临时存档（500000/1000000/1200000/100000/10000 对 level 23 分别是
  B/A/S/C/D）逐个截图，五档字母颜色都对；**改前先把 `userdata.json` 备份到
  `/d/tmp/userdata.backup.json`，跑完 cp 回来并 md5 核对一致**（`scores` 本来就是空的）。
  另外用 `--charts D:/tmp/testcharts`（独立一份超长标题的谱面）验了截断：
  曲名 / Vo. 都在徽章左侧停住并带 `…`。
- 踩坑：`--select-id <musicId>` 会对不上 —— 手机面板的**曲名/封套取 `groups[groupIndex]`，
  而歌手/Vo./难度圆取 `entries[selected]`**，这个调试参数似乎只把其中一边挪过去了，
  于是出现「0075 的曲名 + 9999 的预览音频」。所以测长标题只能另开一个 `--charts` 目录。
  这个 `--select-id` 的不一致是既有问题，没动。
