# 2026-09-13

## hold 尾 flick 触摸屏必须松手才能滑 + 全屏开屏黑底（eb21a96）

用户报两件事：① hold 尾的红色 flick 在触摸屏上很难触发，必须"松手再滑"；黄色稍微好点。
官方是按住不放直接滑就该清。② 全屏模式 + 图片开屏，下次启动会"黑底 + 图片"，
希望无论什么模式，开屏都只是透明底的一张图。

### ① 根因（判定引擎本身没问题，全在 main.cpp 输入层）

先确认引擎侧：hold 尾（kind 2 + `holdTail`）在 `findCandidate` 里是放行的
（`holdTail && !(wantFlick && kind==2)` 那条），所以问题在"喂进去的 lanePos/手势"。

把核心的 HitEvent dump 出来（`hitEvent[...]` 那 8 行日志）看到关键结构 —— **走位 hold**：

```
hitEvent[4] t=5.455 center=1.50 width=3.00 kind=0     ← hold 起点 tap
hitEvent[5] t=5.455 center=1.50 width=3.00 kind=5 end=5.909   ← kind 5 标记（起点轨道 + 终点时间）
hitEvent[6] t=5.682 center=1.50 width=3.00 kind=4      ← tick
hitEvent[7] t=5.909 center=4.50 width=3.00 kind=2      ← **尾判 flick，轨道是终点轨道！**
```

三个原因，全部修掉：

1. **尾判按"按下时的轨道"判定**（主因）。`movePointer` 一直拿 `track.lanePos`
   （FINGERDOWN 时算的）去 `judgement.flick()`。`laneCovers` 要求落在音符中心
   ±(宽度/2+margin)，走位 hold 起步 1.50、尾巴 4.50 → 覆盖范围 [2.2, 6.8]，1.5 落空
   → 按住怎么滑都是 None。**松手再滑能用，是因为新触点从当前手指位置重算了轨道。**
   新增 `flickJudge()`：先试 `lanePos`，None 再试 `restLanePos`。
   `restLanePos` = 手指**低速**时记录的轨道（跟随走位会刷新；滑动过程中速度高不刷新，
   所以不会被"抬头透视"把 lane 拉偏：`lane = worldX/worldY`，手指抬高水平位移会让
   同一屏幕 x 映射到更小的 lane）。
2. **采样周期被静止空档稀释**。触摸屏手指不动时**一个 motion 事件都不发**，所以 flick
   第一帧的 `dt = now - lastMoveTimeSec` 可能是几百毫秒 → 800px/s 被算成 ~100px/s → 刷不出来。
   `dt` 上限钳到 `kFlickMaxSampleSec = 0.03`；空档 > 0.05s 视为"手指停着"→ 清空速度滤波。
3. **一次触点只能 fire 一次 flick 的闩锁**。`track.flicked` 一旦置位，本次触点后面的滑动
   全被无视；hold 途中任何提前/误触的滑动都会把机会用掉。改成可重复触发：
   fire 后把 `travelUp/Side` 归零（同一次连续滑动不会每个事件都触发）+ 60ms 冷却
   （`kFlickRefireSec`）；FINGERUP 的 last-chance 也不再因"已触发过"而跳过。
4. 顺手：`track.isTouch` 显式记录触屏/鼠标（原代码用 `track.fingerId > 0` 猜，
   猜错的话阈值就从触摸的 500px/s 变成鼠标的 900px/s）；FINGERUP 原来硬编码 `true`。

**验证（可复现，不需要真手指）**：`--test-hits` 会把每条 HitEvent 按自己的
`event[1]`（音符轨道）喂给判定引擎，正好可以模拟"滑在正确轨道上"。把那一行的
lane 临时改成 1.5f 就复现旧行为：

```
尾判轨道 4.50 滑 → perfect=11 miss=0
按下轨道 1.50 滑 → perfect=10 miss=1   ← 旧行为，复现漏判
```

回归：main.cpp 改动前后 `--test-hits` 整曲统计**逐字节一致**
（perfect=303 miss=8 tails=5 score=457238；那 8 个 miss 是既有问题，不是回归）；
`--auto` 整曲 0628 HARD → perfect=738 miss=0。

**遗留（未修，用户可能在意）**：走位 hold 的尾巴在 `Judgement.cpp::load()` 里
**不会被打上 `holdTail` 标记**（flagging 用 `candidate.center` vs 标记 center 匹配，
走位时两者不同），所以 `hold.tailIndex` 解析不到 → 它按普通 flick 音符走
（滑到就清、按住不放会 180ms 后 miss），`tails` 统计少算它，松手分级那条路也不生效。
行为上可接受（官方 flick 尾本来就要滑），要改成"按时间窗匹配"才能彻底对齐。
同一处还有已知的 O(n²) 扫描（每根 hold 都遍历全部音符）。

### ② 全屏开屏黑底

图片开屏的透明是靠 `SDL_GL_ALPHA_SIZE=8` + `glClearColor(0,0,0,0)` +
`DwmExtendFrameIntoClientArea(-1,-1,-1,-1)` 实现的（SDL2 没有 SDL_WINDOW_TRANSPARENT，
那是 SDL3）。但窗口一创建就 `SDL_SetWindowFullscreen(FULLSCREEN_DESKTOP)` →
**覆盖整个桌面的窗口被 Windows 的 fullscreen optimizations 接管，DWM 合成被绕过，
逐像素透明失效** → alpha=0 变成不透明黑。

修法：图片开屏期间**一律不进全屏**，用普通无边框窗口（就是窗口模式那套），
加载完在 boot 末尾再应用用户设置的模式（那里原本只做 windowed 的 `SetWindowBordered`）。
另外把开屏窗口尺寸限制在 `SDL_GetDisplayUsableBounds - 16px` 内（万一存档分辨率正好
等于显示器尺寸就会被 FSO 抓走）—— 开屏窗口除了居中那张图整体都透明，缩几像素肉眼不可见。
经典开屏（splashStyle=1，深色底）保持"创建即全屏"不变。

验证：`--window fullscreen` 截图 1920x1080、`--window windowed` 截图 1366x768
（存档里的分辨率），证明全屏是延后生效且 resize 事件把 renderer/core 尺寸都带上了。
顺手把 F 键的 `fullscreen` 状态改成 `SDL_GetWindowFlags()` 查真实状态 ——
以前在设置里切成全屏后首次按 F 会因为本地标志是 false 而"没反应"。
