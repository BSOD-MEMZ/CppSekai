### ★ 这次最大的坑：这套 zig 下 `-isystem` 会顶掉真头
为了让第三方头的警告不盖住自己的，我把 `-Ithird_party` 改成了 `-isystem third_party`，
**整个构建挂掉**：`no type named 'XMVECTOR' in namespace 'DirectX'`。

根因（`zig c++ -E -v` 看 `#include <...> search starts here` 才看出来）：
**zig 的 builtin 搜索目录排在所有 `-isystem` 之前**，而
`toolchain/…/libc/include/any-windows-any/` 里有个 MinGW 版**小写** `directxmath.h`
桩头（只有 `namespace DirectX`，没有 XMVECTOR/XMMATRIX）。Windows 文件系统大小写不敏感，
桩头把真头顶掉了。**`-I` 的优先级在 builtin 之前，只有 `-I` 能钉住真头。**
→ 已写进 build.sh 注释 + AGENTS.md「硬性坑」。

### 做法（`game/SongSelect.cpp`，全部在 `drawSongSelect` 里）

  面板开着时图标外面套一圈薄荷环。`action = SelectSettings` 那条分支删掉（设置走顶栏了）。
- 面板：`vp*` 前缀一整套自绘（半透明深色底 `IM_COL32(40,38,62,232)` + 圆角 22k + dropShadow），

### ★ 这次最大的坑：ImGui 的 hover 给"本帧先提交"的 item
面板画在手机面板**上面**（后提交的顶点），但卡片是在手机面板那些 `InvisibleButton` **之后**
才提交的，于是鼠标同时压在两块上面时，**手机面板的按钮先抢走 `HoveredId`，卡片永远点不动**。
（`ImGui::ItemHoverable` 里那句 `if (g.HoveredId != 0 && g.HoveredId != id) return false`。）
处置：面板开着时把手机面板的难度圆 / 确定 / 两个圆钮**全换成 `ImGui::Dummy`**——
语义上本来也该如此（面板把它整个盖住了）。判据是 `vocalPanelUp`（`gVocalPanelOpen ||
anim > 0`），而且它必须在**帧中靠前**算出来，所以那段 `ui::anim` 被提到了手机面板之前。
同一个理由也解释了滚轮：**不能在整块列表上放一个 `InvisibleButton` 抓滚轮**
（它会先抢 hover），直接读 `io.MouseWheel` 就好。

### 别的两个可复用点
- **裁剪要 `ImGui::PushClipRect` 而不是只 push draw list 的 clip**：前者会同时写
  `window->ClipRect`，于是滚出视野的卡片连**命中测试**一起被剔除（`IsClippedEx`）。
- **参考截图的几何别靠肉眼**：`pngcrop.py` 放大看形状 + 一段 Python（`from pngcrop import
  read_png`）扫行/列找色块边界，量出来的数（卡片 `#DDDEE9`、单选白盘 r=15.5、文字左缘
  = 卡左+56、锁 43x49 正好在卡片正中）比"看着差不多"省事得多。
  踩到的：`png_color_probe.js` 尾部的 `minGminusR/minGminusB` 是 **`>=` 比较**，
  对**淡紫/近白**的目标（g 比 b 小）传 `0` 等于要求 `g>=b`，会一个都不命中——
  量浅色卡那次就这么被骗过一次（不是工具的问题，是阈值用错了）。
